## 슬라이드 3 — 프로젝트 개요 (3/20)

**[정근녕]**

먼저 기존 기술의 한계입니다.

첫째, 기존 스키닝 기술은 손가락을 굽힐 때 관절이 뭉개지고 부피가 사라지는 문제가 가장 큰 문제점입니다.  
또한 음악 연주 흐름과 손의 움직임 제약을 동시에 고려하는 운지법 자동화 도구가 없습니다. 
그리고 악보 파일인 MIDI에서 최종 렌더링 영상까지 이어지는 통합 자동화 시스템이 부재합니다.

이에 저희 프로젝트의 목표는 크게 두 가지입니다.
하나는 음악 파일을 입력받아 자연스러운 손 동작 애니메이션을 자동으로 생성하는 것이고, 이를 통해 생성된 애니메이션을 물리 기반 피부 변형 시뮬레이션으로 주름과 핏줄까지 사실감 있게 렌더링하는 것입니다.

## 슬라이드 4 — 전체 시스템 파이프라인 (4/20)

**[정근녕]**

전체 시스템 파이프라인입니다.

MIDI 파일이 입력되면, 첫 번째는 Python과 DP 알고리즘을 이용해 어떤 손가락으로 어떤 건반을 누를지 , 즉 운지법을 결정합니다. 두 번째로  **IK 시스템**이 C++과 Vulkan 기반으로 관절 각도를 계산합니다. 세 번째로는 **Skinning** 모듈이 UE5의 Chaos Flesh PBD를 활용해 피부 변형을 시뮬레이션합니다. 마지막으로 이수민 팀원의 **렌더링** 모듈이 SVE와 MRQ를 통해 최종 영상을 출력합니다.

하단의 플로우차트를 보시면, MIDI 파싱부터 양손 분리, DP Solver, JSON 출력, IK 목표 설정, Jacobian DLS, ROM 클램핑, 베지어 궤적, Bone Transform까지 이어지고, 이것이 Skeletal Mesh로 들어가서 Chaos Flesh PBD, Deformer Graph, Tension Map, 커스텀 셰이더를 거쳐 렌더링 출력까지 이어지는 파이프라인입니다.

## 슬라이드 5 — Module 1: 지능형 운지법 결정 엔진 (5/20)

**[정근녕]**

제가 담당한 운지법을 결정하는 부분입니다.

초기 버전에서는 개별 음표 단위 탐색과 기본 비용 함수 설계, 손목 방향 힌트 추가를 했습니다. 
V4에서는 화음을 지원할 수 있게 되었고 손가락 간격 제약 적용과 손목 각도 자동 산출을 구현했습니다. 
최종 V5에서는 실제 피아노 연주자의 도메인을 기반으로 성부 분리 분석을 도입하여 멜로디, 저음, 내성 역할을 분류하고, 왼손 방향 오류를 수정했습니다.

오른쪽의 처리 파이프라인을 보시면, MIDI Parser가 Format 0과 1을 모두 지원하고, 피치 밀도 최저점으로 양손을 분리한 뒤, Chord-based DP Solver가 최적 운지를 결정합니다. 이후 손목 물리 모델링으로 Yaw와 Roll 각도를 산출하고, 최종적으로 JSON을 출력하여 IK 모듈로 전달합니다.

## 슬라이드 7 — Module 1: 결과물 (JSON 출력) (7/20)

**[정근녕]**

운지법 엔진의 결과물입니다. 다음 모듈인 IK 시스템으로 전달하기 위한 JSON 데이터 스키마를 보여드리고 있습니다.

왼쪽이 스키마 정의인데, pitch는 MIDI 음고 21에서 108, start_ms와 duration_ms는 시작 시각과 지속 시간, hand는 왼손 또는 오른손, role은 멜로디·베이스·이너 중 하나, finger는 1부터 5, pressure와 key_depth는 velocity 기반 건반 누름 깊이, is_black은 흑건 여부, 그리고 wrist_yaw_deg와 wrist_roll_deg는 손목 각도입니다.

오른쪽은 실제 출력 예시로, 드뷔시 달빛을 연주한 결과물로 첫 화음의 JSON 결과를 보여드리고 있습니다. pitch 60과 64가 각각 오른손 3번, 4번 손가락으로 배정되어 있고, 손목 각도와 pressure 값까지 모두 포함되어 있습니다.

## 슬라이드 10 — Module 2: Jacobian DLS 역운동학 시스템 (8/20)
Jacobian을 기반으로 하는 I학 시스템입니다.

핵심 수식은 다음과 같습니다.
여기서 J는 각 관절이 손끝 위치에 미치는 영향 행렬이고, 
λ는 0.05로 설정하여 불안정한 자세에서 급격한 관절 변화를 방지합니다. 
반복마다 최대 회전량을 제한합니다.

오른쪽은 7단계 반복 연산 과정입니다. 
먼저 타건 목표 좌표를 이전에 입력받은 운지법 결과대로 3D 위치를 설정하고, 우선 Forward Kinematic으로 손목에서 손끝까지의 현재 위치를 계산합니다. 관절 영향 행렬인 Jacobian을 구성하고, DLS 방법으로 관절 회전량을 계산합니다. 관절 한계에 근접하면 자동으로 회전량을 감속하고, 최대 회전량 제한을 적용한 뒤, 관절 범위 내로 고정하여 수렴을 판정합니다.

하단의 표는 관절별 실제 해부학적 범위를 반영하고 있습니다. 추가로 베지어 곡선 타건 궤적과 손목 Yaw/Roll 가이드값 보간도 적용됩니다.

## 슬라이드 14~15 — Module 3: Chaos Flesh PBD 물리 시뮬레이션 (10/20)

다음은 카오스 플레시 PBD 물리 시뮬레이션입니다.
LBS는  관절을 굽히면 부피가 사라지거나 표면이 비틀리는 현상이 발생합니다.

Chaos Flesh PBD를 사용하면, 내부를 사면체로 채워 볼륨을 보존하고, 뼈 움직임에 따라 피부가 자연스럽게 밀리고 변형할 수 있게됩니다.

이를 구현하기 위해 하단은 Flesh Asset Dataflow로, 2개 그래프로 분리 설계했습니다. 
**Dataflow 1번**은 형상(Geometry) 생성을 담당하여 스켈레탈 메시에서 사면체를 생성하고 정점 속성을 전달하여 FleshAsset을 만듭니다. 
(ppt 넘기기)
**Dataflow 2번**은 시뮬레이션 제어를 담당하여 FleshAsset을 로드하고 물성을 설정한 뒤, 본 바인딩과 트라이앵글 바인딩을 수행합니다. 오른쪽에 보이는 것이 실제 UE5 Dataflow 노드 구성입니다.

## 슬라이드 19 — Module 3: 텐션맵 & 디테일 셰이더 (12/20)

**[곽경민 / 이수민]**

다음은 텐션맵과 디테일 셰이더입니다.

구현은 4단계로 진행했습니다.
 **STEP 1**은 장력 시각화 머티리얼 구현으로, 압축과 인장 부위를 파랑과 빨강으로 표시합니다.

 **STEP 3**은 텐션맵을 텍스처로 베이크하는 것으로, 1024x1024 Render Target을 사용합니다.
  **STEP 4**는 텐션값으로 주름·핏줄 변위를 구동하고 노멀맵 미세 디테일을 반영합니다.

## 슬라이드 22 — Module 3: 주름 변위 검증 ③ (13/20)

**[이수민]**

시퀀스 다이어그램입니다. 
매 프레임마다 IK/본이 관절 위치와 각도를 전달하면, 
Chaos Flesh가 변형 표면과 스트레인을 계산합니다. 
구동 어댑터가 마스크를 갱신하고  텐션맵으로 바인딩합니다. 
디테일 머티리얼이 텐션맵, 핏줄맵, 노멀맵, 마스크를 받아 생성하면, 
Chaos Flesh에서 변형 표면 입력 메시를 전달합니다. 
최종적으로 Nanite 테셀/렌더러가 주름과 핏줄의 상태를를 적용하고, 
셰이딩된 노멀을 합성하여 테셀레이션을 수행합니다.

## 슬라이드 23 — Module 3: SVE/RDG 커스텀 렌더링 파이프라인 (14/20)

**[이수민]**

SVE/RDG 커스텀 렌더링 파이프라인입니다. 세 가지 셰이더 분기 검증을 완료했습니다.

**Mode 1**은 Sobel 에지 검출로, 와이어프레임 형태의 에지를 추출합니다. **Mode 2**는 탈색 + 포스터라이즈로, 색상을 단순화한 스타일라이즈드 렌더링입니다. **Mode 3**은 원본 패스스루로, 원본 렌더링을 그대로 출력합니다.

이 커스텀 파이프라인은 향후 최종 렌더링 품질 조정에 활용될 예정입니다.

## 슬라이드 25 — Interface A 상세 (15/20)

**[정근녕]**

Interface A의 상세입니다. 
왼쪽 표는 IK가 사용하는 필드와 목적을 정리한 것입니다. pitch로 건반 3D Target Position을 계산하고, start_ms로 IK 시작 타임라인을 트리거하며, finger로 End Effector 타겟 본을 선택합니다. key_depth는 Fingertip IK 목표 Z축 오프셋으로, wrist_yaw_deg와 wrist_roll_deg는 IK 초기 자세 설정에 활용됩니다.

오른쪽은 pitch에서 건반 3D 좌표로의 변환 규칙으로, 흰건 너비 2.3cm, 흑건 너비 1.3cm, 흰건 길이 15.0cm, 흑건 길이 9.5cm, 최대 건반 누름 깊이 1.0cm의 물리적 치수를 기준으로 좌표를 계산합니다.

## 슬라이드 27 — Interface C 상세 (15/20)

**[이수민]**

Interface C의 상세입니다. Skinning에서 렌더링으로 전달되는 정보로

Skeletal Animation은 IK 결과를 AnimSequence Joint Transform 형태로 그대로 전달하고, Vertex Displacement는 PBD 기반 조직 변형 오프셋을 vertex 들에  전달합니다. Skin Texture는 4K 해상도의 피부 기본 색상 및 질감, Normal Map은 4K 관절 굴곡에 따른 주름 표현, Vein Map은 2K 핏줄 등 피하 조직 가시화, Tension Value는 per-vertex float로 인장, 압축 강도를 Shader 입력으로 전달합니다.

## 슬라이드 29 — 주요 기술적 도전 및 해결 (16/20)

**[정근녕]**

개발 과정에서 겪은 주요 기술적 도전과 해결 방법입니다.

**왼손 운지 방향 오류**로 인한 꼬임현상

**IK 불안정 현상** — 특정 자세에서 관절이 갑자기 뒤집히는 현상이 발생했습니다..

**SVE 초기화 오류** — 엔진 초기화 전에 렌더 확장을 생성하여 크래시가 발생했습니다. 엔진 초기화 완료 후 콜백에서 지연 생성으로 해결했습니다.

**Flesh 시뮬레이션 과부하** — 전신 사면체 생성 시 에디터가 멈추는 문제가 있었습니다. 손·팔 영역만 선택적으로 적용하여 정점 수를 85% 감소시켰습니다.

**UE5 버전 호환 문제** — UE5.6에서 Chaos Flesh API가 변경되어 기존 연동 코드가 중단되었습니다. UE5.5 버전으로 다운그레이드하여 안정성을 확보했습니다.


이건 아직 미해결
**Thumb-under 미지원** — 스케일·아르페지오 구간에서 엄지 넘기기 자동화가 부재합니다. 이는 2학기에 해당 구간을 자동 감지한 후 운지 보상 비용을 적용할 예정입니다.

## 슬라이드 30 — 2학기 졸업프로젝트 계획 (18/20)

**[정근녕]**

2학기 졸업프로젝트 계획입니다.

**운지법 엔진**: 엄지 넘기기 자동 최적화, MIDI 페달 표현 반영, 사용자 손 크기 설정을 추가합니다.

**IK 시스템**: MetaHuman 실제 연동 완성, 손가락 간 충돌 방지, 손목 동작 자연화를 구현합니다.

**Skinning**: 텐션맵 파이프라인 완성, 실제 손 메시로 교체, Nanite 테셀레이션을 적용합니다.

**셰이더**: 물리 기반 스키닝 셰이더, 핏줄·노멀 디테일 통합, PBR 최종 품질 조정을 수행합니다.

오른쪽 로드맵을 보시면, 2학기 착수 후 각 모듈 고도화를 병행하고, 모듈 간 인터페이스 통합 검증, End-to-End 통합 실행, 그리고 최종 결과물로 실시간 연주 시뮬레이션 프로그램과 고품질 렌더링 영상 자동 생성 파이프라인을 완성하는 것이 목표입니다.

**최종 결과물 목표**: 임의의 MIDI 파일 → 운지법 자동 결정 → IK 애니메이션 → 고품질 렌더링 영상 자동 생성
