# 1. 개요

## 1.1 프로젝트 기획 배경

**기술적 니즈**
기존 게임·시뮬레이션의 손가락 움직임은 Linear Blend Skinning(LBS)에 의존한다. 피아노 연주처럼 관절이 깊게 굽는 동작에서 관절 뭉개짐(Candy Wrapper Artifact)과 부피 소실이 발생하고, 주름·핏줄 등 피하 조직이 표현되지 않는다.

**사용자 니즈**
MIDI 데이터만 입력하면 실제 피아니스트의 운지법을 재현하고 영화적 품질의 연주 영상을 생성하는 도구가 없다.

**1학기에서 드러난 추가 문제**
1학기에 각 모듈의 핵심 알고리즘은 검증하였으나, 모듈 간 인터페이스가 문서 수준에만 존재하여 실제 연결 시 수치 불일치가 발생할 가능성이 확인되었다. 2학기는 이를 해소하고 통합하는 것을 주 과제로 삼는다.

## 1.2 기술 동향

| 분야 | 동향 |
|---|---|
| XPBD / FEM | 실시간성을 유지하면서 물리적으로 정확한 변형 시뮬레이션이 확산 |
| LBS | 연산이 빠르나 Candy Wrapper Artifact 발생 |
| DBS | LBS의 부피 감소를 보간으로 보완하나 바깥쪽으로 부푸는 부작용 |
| Chaos Flesh | UE5가 제공하는 FEM 기반 소프트바디. 범용 Skinning 구현에 사용 |
| GPU Skinning | 엔진 기본 스키닝은 정점을 옮기기만 하고 표면 신장률을 계산하지 않아 주름이 생기지 않음. 컴퓨트 셰이더로 대체 가능 |
| Motion Generation | 전신 로코모션은 생성형 AI·강화학습이 도입되었으나, 피아노 연주와 같은 미세 동작은 데이터가 적음 |
| Inverse Kinematics | Jacobian 선형 근사가 고전적 기법. 특이점 회피를 위해 DLS 계열이 사용됨 |

## 2.2 각 기능별 동작 시나리오

### UC-01 MIDI 파일 입력 및 운지법 결정

| 항목 | 내용 |
|---|---|
| 사전조건 | 유효한 Standard MIDI File (Format 0 / 1) |
| 주 흐름 | ① 파일 선택 ② 포맷 확인 ③ 전 트랙의 템포 이벤트를 수집해 템포맵 구성 ④ 음표를 절대 시간(ms)으로 변환 ⑤ 손 분리 ⑥ 화음 그룹화 ⑦ DP로 손가락 배정 ⑧ 손목 각도·건반 좌표 산출 ⑨ JSON·CSV 출력 |
| 대안 흐름 | 88키 범위 밖 음표는 경고 후 제외한다. 두 손으로 배정할 수 없는 음표는 성부 중요도 순으로 최대한 살리고, 남는 음표는 제외하며 사유를 보고한다 |
| 예외 처리 | 지원되지 않는 포맷: 오류 메시지 출력 후 중단. 파일 손상: 크래시 없이 오류 출력 |
| 사후 조건 | 음표별 손가락·손목 각도·건반 3D 좌표를 포함한 JSON이 생성된다 |

# 3. 비기능적 요구사항

## 3.1 사용편리성

- 전문 지식이 없는 사용자도 조작할 수 있도록 위젯 기반 UI를 제공한다.
- 손 크기 프리셋 3종(성인 남성 / 성인 여성 / 아동)을 드롭다운으로 선택한다. **(미구현)**
- 운지법 결과는 명령 한 번으로 일괄 생성한다.

  ```bash
  python tools/run_batch.py --all --metrics --export-ue5
  ```

  21곡 처리·물리 제약 측정·UE5 CSV 생성이 한 번에 수행되며, 곡별 음표 수·제외 수·위반 수가 표로 출력된다.

## 3.2 신뢰성

| 항목 | 기준 |
|---|---|
| 운지법 물리 제약 위반 | 연주 가능한 입력에서 0건 |
| 타이밍 정확도 | MIDI 템포맵 기준 1 ms 미만 |
| 음표 유실 | 파싱 단계에서 0건 (재타격·미종료 음표 포함) |
| 회귀 테스트 | 5종 전부 통과 상태 유지 |
| IK 수렴 | 반복 40회 내 수렴. 발산·떨림 없음 |
| 손상 입력 | 크래시 없이 처리하고 사유를 보고 |

## 3.3 성능

| 항목 | 기준 | 현재 |
|---|---|---|
| 운지법 처리 시간 | 곡당 10초 이내 | 21곡 17.8초 (최대 7.9초) |
| IK 수렴 반복 수 | 40회 이내 | ( ) *담당: 한승현* |
| IK CSV 내보내기 | — | `deb_clai` 248초·7,447프레임을 4초 (Release) |
| Flesh → 스키닝 어댑터 | — | 46 ms → **7 ms** (바인딩 1회 생성 + 정점 계산 병렬화) |
| 전체 프레임 (에디터 PIE) | 60 FPS (16.7 ms) | **약 20 FPS (51 ms)**. GPU 3.7 ms로 한가하고 **게임 스레드가 병목**(기본 44 ms) |
| GPU 스키닝 단독 비용 | ( ) | 미측정. 병목이 어댑터가 아니라 게임 스레드 기본 비용(44 ms)이며, Flesh 솔버·양손 애니메이션 평가·에디터 PIE 오버헤드 중 무엇인지 아직 분리하지 못함 |

## 3.4 이식성

- 운지법 엔진은 Python 표준 라이브러리와 `mido` 만 사용하며 OS에 의존하지 않는다.
- 건반 좌표 변환 모듈은 외부 의존이 없는 순수 함수로 구성한다.
- UE5 측은 엔진 버전 5.5 / 5.6 환경에 맞춘다. **버전 간 Chaos Flesh API 차이가 있어 통일이 필요하다.**

## 3.5 유지관리

- 파트 간 공유 수치는 `shared_constants.py` 한 곳에서 관리하며, 각 모듈이 이를 참조한다. 수치를 복제하지 않는다.
- 건반 좌표 변환식은 `piano_keyboard.py` 가 유일하게 구현한다.
- 지표 정의와 측정 코드를 분리해, 보고서 수치의 산출 근거를 추적할 수 있게 한다.
- 제출 시점의 산출물은 별도 폴더에 보관하고 현행 결과물과 구분한다.

## 3.6 구현상 제약사항

| 항목 | 내용 |

| 엔진 | Unreal Engine 5.5 이상 |

## 3.7 인터페이스

| 인터페이스 | 송신 → 수신 | 포맷 | 핵심 데이터 |
|---|---|---|---|
| A | 01_Fingering → 02_IK | JSON / CSV | `pitch`, `start_ms`, `duration_ms`, **`key_hold_ms`**, **`pedal_down`**, `finger`, `hand`, `role`, `pressure`, `key_depth`, `wrist_yaw_deg`, `wrist_roll_deg`, **`target_x/y/z_mm`** |
| B | 02_IK → 03_Skinning | **CSV 2종** → AnimSequence | `joints.csv` (`frame,time_ms,bone,flex_deg,abd_deg,twist_deg`, 오른손 15행/프레임, 30 FPS), `wrist.csv` (`x/y/z_cm`, `yaw/pitch/roll_deg`). `check_ik_csv.py` 검증 후 `import_ik_csv_to_anim.py` 가 AnimSequence로 변환 |
| C | 03_Skinning(Flesh) → 03_Skinning(GPU) | 정점 버퍼 | 물리 변형된 표면 정점 위치. `UPianoHandFleshInputComponent` → `PianoHandFleshBlend.usf` 에서 `lerp(스키닝, Flesh, Blend)` |
| D | 03_Skinning → 04_Main | Material / Buffer | 최종 정점·노멀, 텐션값 |

**단위 규약**: 길이는 밀리미터(mm)가 기준이다. UE5는 cm를 쓰므로 소비 측에서 ÷10 한다.

**타이밍 규약**: 건반 해제 시점은 `start_ms + key_hold_ms` 다. `duration_ms` 는 Sustain 페달로 늘어난 소리의 지속이며, 이를 해제 기준으로 쓰면 한 손가락이 서로 다른 건반을 동시에 누르는 자세가 만들어진다.

**미확정 항목**

| # | 항목 | 관련 파트 |
|---|---|---|
| 1 | IK가 손목 회전을 내보내지 않음 (`wrist.csv` 의 `yaw/pitch/roll` = 0). 운지법이 산출한 손목 각도가 최종 자세에 반영되지 않는다 | 01 ↔ 02 |
| 2 | IK 각도의 기준 자세 규약 — 프레임 0에서 중간 마디가 84~97° 굽은 채 시작한다. 기본 굽힘이 각도에 포함된 것인지 확인 필요 | 02 ↔ 03 |
| 3 | 왼손 — 현재 오른손(`SKM_MH_Hand_R`)만 연동되어 있다 | 02 ↔ 03 |
| 4 | 손바닥 길이(7.2~8.1 cm)가 IK 손 모델에 없음. `*_metacarpal_r` 4개 본은 데이터 없이 기준 자세 유지 | 02 |
