# 스키닝 모듈 테스트 케이스

03_Skinning은 두 모듈로 나뉜다. **GPU 스키닝(이수민)** 은 주름·핏줄 같은 미시 디테일을, **Chaos Flesh(곽경민)** 는 살 눌림·부피 보존 같은 거시 변형을 담당한다. 두 모듈은 같은 손 메시를 쓰고 최종적으로 Interface C로 연결되므로, 개별 시험과 연결 시험을 나눠 적는다.

> **확정되지 않은 항목은 빈칸으로 두고 `( )` 로 표시한다.** 담당자가 채워 넣는다.

---

# A. GPU 스키닝 (이수민)

## A.1 일반 입력

| 입력 | 내용 |
|---|---|
| 굴곡 애니메이션 | 주먹을 쥐었다 펴는 동작 |
| 피아노 연주 애니메이션 | ( ) IK 모듈 출력 연동 후 |
| 정지 포즈 | T‑pose, 완전 굴곡 |

## A.2 코너 케이스

| # | 케이스 | 입력 예 | 보려는 것 |
|---|---|---|---|
| 1 | 기준선 | 손을 편 정지 상태 | 마디마다 가로 주름이 보이는지. 신장률이 0에 가까운 구간에서 과도한 주름이 생기지 않는지 |
| 2 | 손등 vs 손바닥 | 주먹 쥐기 | 손등은 펴지고 손바닥은 접히는 반대 동작이 각각 올바른 방향으로 나오는지. 이중 게이트 분기 (6.4절 문제) |
| 3 | 이력 주름 | 굽혔다 편 직후 정지 | `RelaxState` 가 프레임 간 유지되어 주름이 남는지. 감쇠 약 0.9초라 **정지 화면으로는 확인 불가**, 시퀀서 렌더로 검증 |
| 4 | 노멀 갱신 | 큰 변위가 생기는 구간 | 변위 후 노멀이 재계산되는지 (6.3절 누락 문제) |
| 5 | 손목 절단면 | 손목 경계 | 노멀이 거칠어지는 알려진 문제. 커프 또는 경계 평활화 전후 비교 |
| 6 | 손바닥 접힘선 | 손바닥 중앙 | 생명선 등은 관절 밴드로 출력되지 않는 알려진 한계. 수작업 맵 필요 여부 확인 |
| 7 | 고밀도 메시 | 정점 77k | PN 테셀레이션 후 성능과 아티팩트 |
| 8 | ( ) | ( ) | ( ) |

# B. Chaos Flesh (곽경민)

## B.1 일반 입력

|---|---|
| 굴곡 애니메이션 | 주먹을 쥐었다 펴는 동작 |

| 손 모델 | `SKM_MH_Hand_R` (4,834 정점) |

## B.2 코너 케이스

| # | 케이스 | 입력 예 | 보려는 것 |
|---|---|---|---|
| 1 | 기준선 | T‑pose 정지 | 사면체가 메시 표면을 벗어나지 않는지, 시뮬레이션이 발산하지 않는지 |
| 2 | 애니메이션 추종 | 주먹 쥐기 | Flesh가 뼈 움직임을 따라가는지 (5.4.6에서 확인) |
| 3 | 손끝 지연·어긋남 | 굴곡 애니메이션의 손끝 | 손끝이 늦게 따라오는 알려진 문제. 타이밍·중력·바인딩 영역을 바꿔도 동일하고 정지 상태에서도 남아, 지연이 아니라 **형태 차이**로 추정. 위치를 추출해 수치로 확인 |
| 4 | 부위별 바인딩 | VertexSelection 설정 전후 | VertexSelection이 비어 있으면 모든 정점이 뼈에 묶여 안쪽 탄성이 반영되지 않음. 설정 후 변형 차이 |
| 5 | Vertex Inflation | 0.5 / 조정값 | 얇은 손가락이 부풀어 오르는지 |
| 6 | 사면체 생성기 | IsoStuffing vs TetWild | IsoStuffing은 MetaHuman 메시에서 손가락 볼륨 생성 실패 (6.5절). TetWild 전환 근거 |
| 7 | LBS 대비 비교 | Flesh On / Off | 부피 보존 효과를 눈과 수치로 비교. **미실시** |

# C. 연결 시험 (Interface C)

Flesh가 계산한 표면 위치를 GPU 스키닝 파이프라인의 입력으로 넘기는 구조를 시험한다. **어댑터는 미구현이므로 아래는 계획이다.**

| # | 케이스 | 보려는 것 |
|---|---|---|
| 1 | 전달 경로 | Flesh 변형 표면이 GPU 스키닝 입력으로 들어가는지 |
| 2 | 이중 적용 방지 | 같은 변형이 두 번 적용되지 않는지 (Flesh가 이미 옮긴 정점을 LBS가 다시 옮기지 않아야 함) |
| 3 | 부피 보존 항 | C3의 `1/λ²` 추정값을 Flesh 실제 계산으로 대체했을 때의 차이 |
| 4 | 성능 | 두 모듈을 함께 돌렸을 때의 프레임 비용 |
| 5 | ( ) | ( ) |

전달 방식(Buffer vs Texture)은 미결정이다.

# D. 결과 정리 방식

- 케이스 × 지표 표 하나로 정리한다. GPU와 Flesh를 나눠 적고, 연결 시험은 따로 둔다.
- 실패하거나 미실시인 케이스도 빼지 않고 "알려진 한계"로 함께 적는다.
- 현재 해당하는 항목은 다음과 같다.

| 모듈 | 알려진 한계 | 후속 |
|---|---|---|
| GPU | 손바닥 접힘선(생명선 등)이 관절 밴드로 출력되지 않음 | 수작업 맵 추가 |
| GPU | 이력 주름 감쇠 약 0.9초 — 정지 화면 확인 불가 | 시퀀서 렌더로 검증 |
| GPU | 손목 절단면 노멀 거침 | 커프 씌우기 또는 경계 평활화 |
| GPU | 성능 미측정 (정점 77k, 6‑pass) | 프레임 비용 측정 |
| Flesh | 손끝 어긋남 — 지연이 아니라 형태 차이로 추정 | 위치 추출 후 수치 확인 |
| Flesh | Vertex Inflation 0.5 미조정 | 얇은 손가락 영향 확인 |
| Flesh | LBS 대비 비교 검증 미실시 | On/Off 비교 |
| Flesh | 부위별 바인딩 적용 확인 남음 | VertexSelection 설정 |
| 연결 | Flesh → GPU 어댑터 미구현 | 전달 방식 결정 후 구현 |
