# 스키닝 모듈 테스트 케이스

03_Skinning은 두 모듈로 나뉜다. **GPU 스키닝(이수민)** 은 주름·핏줄 같은 미시 디테일을, **Chaos Flesh(곽경민)** 는 살 눌림·부피 보존 같은 거시 변형을 담당한다. 두 모듈은 같은 손 메시를 쓰고 최종적으로 Interface C로 연결되므로, 개별 시험과 연결 시험을 나눠 적는다.

> **확정되지 않은 항목은 빈칸으로 두고 `( )` 로 표시한다.** 담당자가 채워 넣는다.

# A. GPU 스키닝 (이수민)

## A.1 일반 입력

| 입력 | 내용 |
|---|---|
| 굴곡 애니메이션 | 주먹을 쥐었다 펴는 동작 |
| 피아노 연주 애니메이션 | `A_IK_DebClai` (드뷔시 '달빛', 248초·7,447프레임) |
| 정지 포즈 | T‑pose, 완전 굴곡 |

## A.2 코너 케이스

| # | 케이스 | 입력 예 | 보려는 것 |
|---|---|---|---|
| 1 | 기준선 | 손을 편 정지 상태 | 마디마다 가로 주름이 보이는지. 신장률이 0에 가까운 구간에서 과도한 주름이 생기지 않는지 |
| 2 | 손등 vs 손바닥 | 주먹 쥐기 | 손등은 펴지고 손바닥은 접히는 반대 동작이 각각 올바른 방향으로 나오는지. 이중 게이트 분기 (6.4절 문제) |
| 3 | 이력 주름 | 굽혔다 편 직후 정지 | `RelaxState` 가 프레임 간 유지되어 주름이 남는지. 감쇠 약 0.9초라 **정지 화면으로는 확인 불가**, 시퀀서 렌더로 검증 |
| 4 | 노멀 갱신 | 큰 변위가 생기는 구간 | 변위 후 노멀이 재계산되는지 (6.3절 누락 문제) |
| 5 | 손목 절단면 | 손목 경계 | 노멀이 거칠어지는 알려진 문제. 커프 또는 경계 평활화 전후 비교 |
| 6 | 손바닥 접힘선 | 손바닥 중앙 | 생명선 등은 관절 밴드로 출력되지 않는 알려진 한계. 수작업 맵 필요 여부 확인 |
| 7 | 고밀도 메시 | `SKM_MH_Hand_R_Dense` (74,186 정점) | PN 테셀레이션 후 성능과 아티팩트 |
| 8 | 개인별 손 비율 | Phase 5 비율 조정 | 비율을 바꿔도 주름 위치가 관절에 붙어 있는지. **Flesh 사용 시에는 꺼야 함** (2026-10-27 합의) |

## A.3 지표

| 지표 | 정의 | 기준 |
|---|---|---|
| 프레임 비용 | 6개 패스 각각의 GPU 시간 | 미측정. 전체 GPU 는 3.7~4.6 ms 로 한가하다 |
| 텐션값 분포 | 정점 컬러 `R` 신장 / `G` 뼈 방향 압축 / `B` 가로 압축 / `A` 릴랙스 슬랙 | ( ) |
| 노멀 연속성 | 인접 정점 간 노멀 각도 차의 최대값 | ( ) |
| 이력 감쇠 시간 | 굴곡 해제 후 주름이 사라지기까지 | 약 0.9초 |
| 시각 품질 | 참고 사진 대비 정성 평가 | 정성 |

측정 방법: `stat unit` · `stat gpu` ( ) *담당: 이수민*

# B. Chaos Flesh (곽경민)

## B.1 일반 입력

| 입력 | 내용 |
|---|---|
| 굴곡 애니메이션 | 주먹을 쥐었다 펴는 동작 |
| 재생 레벨 | `L_FleshTest` |
| 손 모델 | `SKM_MH_Hand_R` (4,834 정점) |

## B.2 코너 케이스

| # | 케이스 | 입력 예 | 보려는 것 |
|---|---|---|---|
| 1 | 기준선 | T‑pose 정지 | 사면체가 메시 표면을 벗어나지 않는지, 시뮬레이션이 발산하지 않는지 |
| 2 | 애니메이션 추종 | 주먹 쥐기 | Flesh가 뼈 움직임을 따라가는지 (5.4.6에서 확인) |
| 3 | 손끝 지연·어긋남 | 굴곡 애니메이션의 손끝 | 손끝이 늦게 따라오는 알려진 문제. 타이밍·중력·바인딩 영역을 바꿔도 동일하고 정지 상태에서도 남음. **수치 확인**: 정지 시 0.2~0.7 cm(형태 차이), 움직일 때 1.3~4.6 cm이고 이동 반대 방향(지연, 약 한 프레임 분량) |
| 4 | 부위별 바인딩 | VertexSelection 설정 전후 | VertexSelection이 비어 있으면 모든 정점이 뼈에 묶여 안쪽 탄성이 반영되지 않음. **측정**: 손가락 묶음 시 정지 어긋남이 30~40% 감소, 움직일 때 지연은 변화 없음 |
| 5 | Vertex Inflation | 0.5 / 조정값 | 얇은 손가락이 부풀어 오르는지. 댐핑 0.1 → 0.5, 팽창 0.5 → 0 조정은 **미시도** |
| 6 | 사면체 생성기 | IsoStuffing vs TetWild | IsoStuffing은 MetaHuman 메시에서 손가락 볼륨 생성 실패 (6.5절). TetWild 전환 근거 |
| 7 | 스키닝 대비 비교 | `Blend` 0 / 0.5 / 1 | 부피 보존 효과를 눈과 수치로 비교. 비교 대상은 순수 LBS 가 아니라 **수민 파이프라인**(DQS/LBS + Implicit Skinning + 부피 팽창 + 관절 주름 + 텐션 + UV 이음매 용접)이다 |
| 8 | IK 급점프 구간 | 한 프레임에 40~120° 점프하는 구간 | Flesh 가 안정적으로 따라오는지. **미확인** |

## B.3 지표

| 지표 | 정의 | 기준 |
|---|---|---|
| 바인딩 에러 | 로그에 기록되는 바인딩 실패 뼈 수 | 0 (뼈 22개 전부) |
| 사면체 정점 수 | 생성 결과 | 5,688 |
| 렌더 메시 바인딩 | `GenerateSurfaceBindings` 결과 | 74,186 정점, 고아·재부모 정점 0 |
| 표면 두께 차 | Flesh 표면과 스키닝 표면의 거리 (정지 자세) | 평균 약 0.3 cm (Flesh 가 더 두꺼움) |
| 시뮬레이션 안정성 | 발산·폭발 발생 프레임 수 | 0. 단 주먹을 쥘 때 가장 안쪽 살이 지글거림 (자기충돌 없음) |
| 프레임 비용 | 어댑터 포함 프레임 시간 | 어댑터 7 ms. 전체 51 ms (약 20 FPS) |
| 손끝 어긋남 (정지) | 손끝 정점의 Flesh–스켈레탈 메시 LBS 거리 (cm), 속도 10 cm/s 미만 | 0.2~0.7 cm. 손가락 묶음 시 0.2~0.5 |
| 손끝 어긋남 (움직임) | 같은 거리, 속도 10 cm/s 이상 | 1.3~4.6 cm, 어긋남 ≈ 이동 반대 방향 성분 (Flesh 가 뒤처짐) |

측정 방법: Output Log 의 `[FleshInput]` 로그 (정점 수·편차·렌더 패스·프레임 시간), `stat unit`. 손끝 어긋남은 `[FleshTip]` 로그 (`UPianoHandFleshInputComponent` 의 `bLogTipError`, 60틱마다 손가락별 `tip`·`group`·`along`·`speed`, 에디터 빌드 전용). `L_FleshTest` 에서 `A_IK_DebClai` 재생, 손가락 `VertexSelection` 0 / 전부 1 두 조건 비교

# C. 연결 시험 (Interface C)

Flesh가 계산한 표면 위치를 GPU 스키닝 직후에 섞는다. **어댑터는 구현·검증 완료다** (2026-10-27 합의).

| # | 케이스 | 보려는 것 | 결과 |
|---|---|---|---|
| 1 | 정점 수 일치 | Flesh 반환 정점 수 = 렌더 메시 정점 수 | 74,186 = 74,186 |
| 2 | 정점 순서·좌표계 | 휴지 자세 편차 | 평균 0.27 cm, 최대 0.35 cm → 이음매 매핑 불필요 |
| 3 | 렌더 패스 실행 | 매 프레임 실행되는지 | 301회 중 301회 (실패 0) |
| 4 | 좌표 변환 | 변환이 필요한지 | 불필요 (변환 전후 편차 동일) |
| 5 | 성능 | 어댑터 비용 | 46 ms → **7 ms** (바인딩 1회 생성 + 정점 계산 병렬화) |
| 6 | `Blend` 효과 | 0 / 0.5 / 1 비교로 살 눌림·부피 이득 정리 | **미실시** |
| 7 | 프레임 지연 | 게임 → 렌더 스레드 전달로 한 프레임 밀릴 수 있음 | **미확인** |

전달은 Buffer 방식이며, `lerp(스키닝, Flesh, Blend)` 를 컴퓨트 셰이더로 수행한다.

# D. 결과 정리 방식

- 케이스 × 지표 표 하나로 정리한다. GPU와 Flesh를 나눠 적고, 연결 시험은 따로 둔다.
- 실패하거나 미실시인 케이스도 빼지 않고 "알려진 한계"로 함께 적는다.
- 현재 해당하는 항목은 다음과 같다.

| 모듈 | 알려진 한계 | 후속 |
|---|---|---|
| GPU | ~~손바닥 접힘선 미출력~~ → Phase 4 에서 해결 | — |
| GPU | 이력 주름 감쇠 약 0.9초 — 정지 화면 확인 불가 | 시퀀서 렌더로 검증 |
| GPU | 손목 절단면 노멀 거침 | 커프 씌우기 또는 경계 평활화 |

| Flesh | 손끝 어긋남 — 정지 0.2~0.7 cm(형태), 움직임 1.3~4.6 cm(약 한 프레임 지연) | 정지(`Play Rate` 0) 측정, 지연 ms 환산, 원인 분리 |
