## 4.3 핵심 알고리즘

### 4.3.1 Chord-based Dynamic Programming

- **상태**: `(현재 화음의 손가락 튜플, 점유 집합)`
  점유 집합 항목은 `(화음 인덱스, 화음 내 위치, 손가락)` 이다.
- **전이**: 직전 화음의 점유를 `required_hold` 기준으로 만료 처리한 뒤 현재 화음의 점유를 더한다.
- **비용**: 손목 이동 + 손가락 난이도 + 흑건 패널티 + 성부 선호 + 레가토 연속성 + 동시 누름 충돌 + 아르페지오 방향성 + 교차 패널티 + **순간 단위 제약 위반 패널티**
- **가지치기**: 화음당 상위 120개 상태 유지 (점유 집합이 상태에 포함되어 경로마다 갈라지므로)

### 4.3.2 물리 제약 (순간 단위)

시각 `t` 에서 한 손이 점유 중인 음표 집합을 `H(t)` 라 할 때, 모든 `t` 에 대해 다음이 성립해야 한다.

| # | 제약 | 내용 |
|---|---|---|
| C1 | 손가락 유일성 | `H(t)` 의 음표는 서로 다른 손가락을 가진다 |
| C2 | 손 범위 | 모든 손가락 쌍이 `MAX_SPAN` 이내 |
| C3 | 순서 | pitch 오름차순과 손가락 번호가 단조. **단 엄지는 제외** (손바닥 아래로 지나가므로) |

`H(t)` 는 온셋에서만 늘어나므로 모든 온셋 시점만 검사하면 충분하다.

## 5.3 핵심 알고리즘

**Weighted Damped Least Squares**

```
Δθ = W⁻¹ Jᵀ (J W⁻¹ Jᵀ + λ² I)⁻¹ Δe
```

- `λ` : 감쇠 계수. 특이점 근방에서 역행렬 발산을 억제
- `W⁻¹` : 관절 한계 근접도에 따른 가중치. 한계에 가까울수록 0에 근접시켜 부드럽게 감속
- 반복 상한 40회, 허용 오차 0.01 — **cm 가 아니라 IK 내부 단위이며 약 0.05 cm 에 해당한다**
- 매 반복 끝에 관절 각도를 ROM 내로 하드 클램프

**손목 궤적**: 지수 감쇠 보간으로 목표 위치에 접근하면서, **남은 이동 거리에 비례해 손목을 들어 올린다.**
이동이 클수록 더 높이 뜨고 목표에 가까워질수록 내려와, 결과적으로 아치처럼 보이는 경로가 된다.

> **정정 (10/29).** 이 절은 2차 제출 직전까지 "2차 베지어 곡선으로 아치형 경로를 생성한다"로
> 적혀 있었으나 코드와 다르다. `Vulkan_IK_Tutorial.cpp` 에 베지어 보간은 없다.

## 5.4 Interface B — 인계 형식

IK는 UE 없이 **CSV 두 개**만 내보내고, AnimSequence 변환은 스크립트가 한다.

```
IK 프로그램 ─▶ joints.csv + wrist.csv ─▶ check_ik_csv.py ─▶ import_ik_csv_to_anim.py ─▶ AnimSequence
```

**`joints.csv`** : `frame,time_ms,bone,flex_deg,abd_deg,twist_deg` (오른손 15행/프레임, 30 FPS)

| 열 | 의미 |
|---|---|
| `time_ms` | `frame × 1000 / 30` (±1 ms) |
| `bone` | 뼈 이름 (필수 15개 + `*_metacarpal_r` 4개 선택) |
| `flex_deg` | 굴곡. **닫히는 방향이 +** |
| `abd_deg` | 벌림 (외전·내전) |
| `twist_deg` | 축 회전 |

각도는 **기준 자세 대비 변화량(도)** 이며 MetaHuman 기본 자세에서 0이다.

**`wrist.csv`** : `frame,time_ms,x_cm,y_cm,z_cm,yaw_deg,pitch_deg,roll_deg`

**IK `joints[j]` → UE 뼈 대응**

| 손가락 | IK 인덱스 | UE 뼈 |
|---|---|---|
| 엄지 | `[0] [1] [2]` | `thumb_01_r`, `thumb_02_r`, `thumb_03_r` |
| 검지~소지 | `[0]` MCP / `[1]` PIP / `[2]` DIP | `<finger>_01_r` / `_02_r` / `_03_r` |
| | 없음 | `<finger>_metacarpal_r` (생략 시 기준 자세 유지) |

`joints[3]` 은 손가락 끝 위치일 뿐 각도를 갖지 않는다.

**현재 상태**: `deb_clai` (248초, 7,447프레임) 내보내기 4초(Release), `check_ik_csv.py` RESULT OK, `A_IK_DebClai` 생성 성공. **오른손만 연동**되어 있다.

`UMeshDeformer` 를 상속하여 엔진 스킨 캐시를 커스텀 컴퓨트 셰이더로 대체한다.

| 셰이더 | 파일 | 진입점 |
|---|---|---|
| `FPianoHandSkinDeformerCS` | `CustomSkinningDeformer.usf` | `DeformCS` |
| `FPianoHandTensionAccumulateCS` | `CustomSkinningTension.usf` | `AccumulateCS` |
| `FPianoHandTensionResolveCS` | `CustomSkinningTension.usf` | `ResolveCS` |
| `FPianoHandDetailDisplaceCS` | `CustomSkinningDetail.usf` | `DisplaceCS` |
| `FPianoHandNormalAccumulateCS` | `CustomSkinningDetail.usf` | `NormalAccumulateCS` |
| `FPianoHandNormalResolveCS` | `CustomSkinningDetail.usf` | `NormalResolveCS` |

## 6.2 6-Pass 파이프라인

| 순서 | 패스 | 스레드 단위 | 역할 |
|---|---|---|---|
| ① | `DeformCS` | 정점 | 본 행렬로 위치·탄젠트 계산 (LBS / DQS) |
| ② | `AccumulateCS` | 삼각형 | rest 평면 기저에서 변형 그래디언트 `F = [p₁ p₂][u₁ u₂]⁻¹`, `C = FᵀF` 를 컴포넌트 공간 3×3 텐서로 올려 6성분 고정소수점 원자 덧셈 |
| ③ | `ResolveCS` | 정점 | 평균 `C3` 를 rest 탄젠트 평면(T, B)에 투영해 2×2 고유분해 → 주신장 `λ_max` / `λ_min` |
| ④ | `DisplaceCS` | 정점 | 뼈 축을 아는 유일한 패스. `λ_bone`·`λ_perp` 산출, 넓이비 `J = λ₁λ₂` 로 부피 보존 `1/J`, 주름 변위 |
| ⑤ | `NormalAccumulateCS` | 삼각형 | 변위 후 면 노멀 누적 |
| ⑥ | `NormalResolveCS` | 정점 | 노멀 정규화 |

## 6.3 주요 설계 요소

| 요소 | 내용 |
|---|---|
| 텐션 계산 | 변의 신장률을 atomic int 고정소수점으로 누적 후 해소 |
| 부피 보존 | 넓이비 `J = λ₁λ₂` 기반 `1/J`. (Phase 3c 이전에는 `1/λ²` 등방 근사였음) |
| 정점 컬러 채널 | `R` 신장 (λ_max−1) · `G` 뼈 방향 압축 (1−λ_bone) · `B` 가로 방향 압축 (1−λ_perp) · `A` 릴랙스 슬랙. 관절 주름은 `G` 로만 구동 |
| 관절 종류 베이크 | 마스크 `B` 채널에 관절 코드 (0.2 MCP / 0.4 PIP / 0.6 DIP / 0.8 엄지 MP / 1.0 그 외). 16비트 PNG → `TC_HDR` |
| 주름 단면 | Bando 식 `S(l) = d(l/w−1)e^(−l/w)`. 바닥이 V 자로 날카롭고 둔덕은 0.4배 억제 |
| 밀도 확보 | **에셋 PN 테셀레이션**. Nanite 메시는 passthrough 정점 팩토리를 쓰지 않아 커스텀 스키닝을 우회하므로 사용하지 않음 |
| 이력 주름 | `RelaxState` 를 프레임 간 유지하여, 폈다 놓은 직후 주름이 남도록 함. 감쇠 약 0.9초 |
| 손등/손바닥 이중 게이트 | 손등과 손바닥은 주름 생성 조건이 반대이므로 스킨 웨이트 기반으로 분기 |
| 관절 위치 판별 | 스킨 웨이트로 관절 밴드 결정. `s` 좌표 원점을 뼈 피벗이 아니라 **밴드 중심**(50/50 스킨웨이트 선)으로 이동 |
| 미세 노멀 이방성 | 샘플한 기울기를 뼈 방향으로 분해해 압축 축은 `MicroAniso`, 신장 축은 `MicroFlatten` 으로 스케일 |

# 7. 컴포넌트 C4 — 03_Skinning (Flesh) 설계

## 7.1 기능 정의

손 내부를 사면체로 채워 뼈에 묶고 PBD로 시뮬레이션한다. 눌린 살이 부피를 유지하려 옆으로 밀려나는 거시 변형을 담당한다.

## 7.2 Dataflow 그래프

1학기에는 Geometry 생성과 바인딩을 두 그래프로 나눴으나, 대상이 손 하나뿐이고 파라미터를 자주 바꿔야 해 **단일 그래프로 통합**하였다.

```
SkeletalMesh
  ├─ SkeletalMeshToCollection_0 (Import Transform Only)
  └─ SkeletalMeshToCollection
        └─ CreateTetrahedron (TetWild)
              └─ SetFleshDefaultProperties
                    └─ SetFleshBonePositionTargetBinding
                          └─ FleshAssetTerminal
```

| 노드 | 역할 | 설정 |
|---|---|---|
| `SkeletalMeshToCollection` | 내부 포맷 변환 | 지오메트리 포함 |
| `CreateTetrahedron` | 사면체 생성 | **TetWild** (IsoStuffing은 손가락 볼륨 생성 실패) |
| `SetFleshDefaultProperties` | 물성 설정 | `Vertex Damping` 0.1 · `Vertex Inflation` 0.5 (조정 미시도) |
| `SetFleshBonePositionTargetBinding` | 뼈 바인딩 | 뼈 22개, 탐색 반경 1.0, `VertexSelection` 으로 묶을 정점 선택 (7.5절) |

## 7.3 손 모델 이력

| 시기 | 메시 | 정점 | 비고 |
|---|---|---:|---|
| 1학기 | `fbx_Clean` | — | 전신, Bone Filter로 손·팔만 |
| 2학기 초 | `SKM_MannyXR_right` | 3,239 | UE 5.6 VR 템플릿 |
| 현재 | `SKM_MH_Hand_R` | 4,834 | MetaHuman 오른손 |

시뮬레이션에는 PN 테셀레이션 전 원본(4,834 정점)을, 렌더링에는 고밀도 메시(77k 정점)를 쓴다.

## 7.4 C3 와의 역할 분담

| | C3 GPU 스키닝 | C4 Chaos Flesh |
|---|---|---|
| 변형 근거 | 스킨 웨이트 + 변 신장률 | 사면체 볼륨 물리 시뮬레이션 |
| 표현 대상 | 주름·핏줄·미세 노멀 | 살 눌림·부피 보존 |
| 스케일 | 미시 디테일 | 거시 변형 |

**Interface C 어댑터는 구현·검증 완료다** (2026-10-27 합의, 곽경민·이수민).

| 파일 | 역할 |
|---|---|
| `Source/pianohand_simulator/Flesh/PianoHandFleshInput.{h,cpp}` | 게임 스레드 컴포넌트 `UPianoHandFleshInputComponent` + 렌더 스레드 패스 `AddFleshBlendPass` |
| `Shaders/Private/PianoHandFleshBlend.usf` | `Out = lerp(Skinned, Flesh, Blend)` |

C3 의 스키닝 패스 **바로 뒤**에 1줄 호출로 연결한다. C3 측 변경은 `include` 1줄 + 호출 1줄이며, Flesh 데이터가 없으면 아무 일도 하지 않는다. 속성 `Blend` 는 0 = 스키닝만, 1 = Flesh만이다.

**검증 결과**

| 항목 | 결과 |
|---|---|
| Flesh 정점 수 vs 렌더 메시 정점 수 | 74,186 = 74,186 (일치) |
| 휴지 자세 편차 | 평균 0.27 cm, 최대 0.35 cm → 이음매 매핑 불필요 |
| 렌더 패스 실행 | 301회 중 301회 (실패 0) |
| 좌표 변환 | 불필요 |
| 어댑터 비용 | 46 ms → **7 ms** (바인딩 1회 생성 + 정점 계산 병렬화) |

## 7.5 멤버 data / 멤버 함수

**물성** (`SetFleshDefaultProperties`)

| 항목 | 값 |
|---|---|
| `Vertex Damping` | 0.1 |
| `Vertex Inflation` | 0.5 |

> 댐핑 0.1 → 0.5, 팽창 0.5 → 0 조정은 **미시도**다.

**뼈 바인딩** (`SetFleshBonePositionTargetBinding`)

| 항목 | 내용 |
|---|---|
| 대상 뼈 | 22개 (컬렉션 안에서 **뼈 이름**으로 찾는다) |
| 탐색 반경 | 1.0 — 0 으로 두면 마지막 뼈(`_03`)보다 바깥에 있는 손끝 정점이 바인딩 범위 밖에 남는다 |
| `VertexSelection` | 묶을 정점 집합. **비워 두면 전부 묶인다** |

`VertexSelection` 핀이 처음에 연결되지 않아 한 번 시험이 무효였다(전부 묶인 채로 측정함).
연결하고 가중치 속성을 저장한 뒤 선택이 적용되는 것을 확인했다.

| 조건 | 결과 |
|---|---|
| 전부 0 (묶이는 정점 없음) | 손이 바로 떨어진다 |
| 손가락만 0 (손가락 풀림) | 정지 어긋남 0.4~0.7 cm. **움직일 때 지연은 그대로** |
| 전부 1 (묶음) | 정지 어긋남이 30~40% 줄어든다 (약지 0.6 → 0.4 cm) |

손가락만 풀어도 지연이 남는 것은, 손가락 안의 사면체가 단단해서 손바닥을 따라 같이 끌려가기 때문으로 보인다.

**`UPianoHandFleshInputComponent` 속성**

| 속성 | 기본값 | 역할 |
|---|---|---|
| `bEnabled` | `true` | 어댑터 on/off |
| `Blend` | `1.0` | 0 = 스키닝만, 1 = Flesh만 |
| `bFastRead` | `true` | 바인딩 1회 생성 + 정점 계산 병렬화 (46 ms → 7 ms) |
| `DebugLiftCm` | `0.0` | 동작 확인용 강제 변위 |
| `bLogDiagnostics` | `true` | `[FleshInput]` 진단 로그 |
| `bLogTipError` | `true` | `[FleshTip]` 손끝 어긋남 로그 (에디터 빌드 전용) |
| `TipLogInterval` | `60` | 손끝 로그 주기 (틱) |

# 8. 컴포넌트 C5 — 04_Main 설계

2차 시점에 **미구현**이다. 아래는 설계안이며, 11/23 주차부터 착수한다.
04_Main 은 다른 모듈과 달리 새로운 알고리즘이 없고, 이미 확정된 좌표계·프레임 레이트를
그대로 쓰는 조립 작업이다. 그래서 2차에서는 뒤로 미루고 통합을 먼저 했다.

| 항목 | 설계안 | 근거가 되는 기존 결정 |
|---|---|---|
| 카메라 제어 | 고정 카메라(건반 전체)와 추적 카메라(연주 중인 손)를 두고 시퀀서에서 전환한다. 프레이밍 범위는 A0(MIDI 21) 좌측 모서리부터 C8까지, 즉 건반 전폭 1,220 mm 를 기준으로 잡는다. | `shared_constants.py` 의 건반 원점·옥타브 폭 |
| UI 구성 | 곡 선택(결과 JSON 목록), 재생·일시정지·배속, 손 크기 프리셋 선택(UC‑02), 카메라 전환. 연주 중에는 UI 를 숨겨 렌더 화면을 가리지 않는다. | 요구사항 UC‑02 (손 크기 프리셋, 미구현) |

| 인터페이스 D | 03_Skinning 의 최종 렌더 결과를 받아 화면·영상으로 내보낸다. 스키닝 쪽에서 별도 자료 구조를 넘기지 않고, UE5 레벨에 배치된 액터를 그대로 촬영하는 방식이다. | 5.4절 인터페이스 정의 |

**담당**: 정근녕. 운지법 엔진이 안정화되어 2차 이후 여력이 생겼고,
건반 좌표계와 프레임 레이트를 가장 잘 아는 쪽이 조립을 맡는 편이 낫다는 판단이다.
