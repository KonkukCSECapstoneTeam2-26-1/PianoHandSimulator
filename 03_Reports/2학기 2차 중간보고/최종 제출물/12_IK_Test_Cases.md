# IK 모듈 테스트 케이스

IK 모듈 테스트 결과를 뽑기 위한 입력 구성과 지표를 정리한다. 세부 케이스를 다 다루지는 않고, 일반 연주와 코너 케이스 몇 개만 확인한다.

## 1. 일반 입력

기존 MIDI 3개를 일반 연주 케이스로 쓴다.

| 입력 | 위치 |
|---|---|
| `test.mid` | `05_Resources/MIDI_Inputs/` |
| `v2_test.mid` | `05_Resources/MIDI_Inputs/` |
| `complex_test.mid` | `05_Resources/MIDI_Inputs/` |

## 2. 코너 케이스

케이스마다 2~4마디 정도의 짧은 입력을 만든다. 각 케이스는 `Vulkan_IK_Tutorial.cpp`에서 실패할 만한 지점을 겨냥한다.

| # | 케이스 | 입력 예 | 보려는 것 (코드 근거) |
|---|---|---|---|
| 1 | 기준선 | 흰 건반 하나를 길게 누르기 | 수렴 여부와 반복 수 (반복 40회, tolerance 0.01). 오차가 거의 0이어야 정상 |
| 2 | 검은 건반 + 소지·엄지 | F#, C# 등을 5번·1번 손가락으로 | 마디 길이를 MetaHuman 실측값으로 바꾼 뒤 소지 오차가 35%에서 57%로 늘어난 알려진 문제(`64f14ef`). 결과에 그대로 드러나야 함 |
| 3 | 도달 한계 | 1번·5번 손가락으로 옥타브, 9도 화음 | 목표가 손이 닿는 범위 밖일 때 관절 제한 안에서 멈추는지, 발산하거나 떨리지 않는지 |
| 4 | 큰 도약 | C3 → C6을 짧은 간격으로 | 손목 이동(`arcMultiplier`, `wristReachMargin`)과 손끝 지연 |
| 5 | 빠른 반복·트릴 | 16분음표 트릴, 같은 음 연타 | 60 Hz 내부 계산과 웜스타트에서 프레임 사이 각도가 튀는지 |
| 6 | 건반 양 끝 | A0, C8 포함 | 음높이 `clamp(21, 108)` 경계와 건반 위치 계산 |
| 7 (선택) | 양손 근접·교차 | 두 손이 같은 옥타브에 있을 때 | 왼손·오른손 손목 목표가 겹치는 경우 |

## 3. 지표

모든 케이스에 같은 지표를 쓴다. 출력은 `PH_EXPORT_CSV`로 내보낸 관절 각도 CSV(30 FPS)를 기준으로 하고, `06_Project/pianohand_simulator/Scripts/check_ik_csv.py`를 확장해 계산한다.

| 지표 | 정의 |
|---|---|
| 손끝-건반 오차 | 평균, 최대, 1 cm 이상인 비율. 건반을 누른 뒤 150 ms 이후 구간만 집계 |
| 수렴 | 평균·최대 반복 수, 40회 안에 수렴하지 못한 프레임 비율 |
| 관절 제한에 걸린 비율 | 손가락별로 각도가 제한값에 걸린 프레임 비율 |
| 떨림 | 인접 프레임 사이 관절 각도 변화량의 최대값 |

## 4. 결과 정리 방식

- 케이스 × 지표 표 하나로 정리한다.
- 2번(검은 건반 소지)과 3번(도달 한계)처럼 실패하는 케이스도 빼지 않고 "알려진 한계"로 함께 적는다.
- 실패 케이스는 원인(마디 길이, 손목 위치 보정 미적용 등)과 후속 작업을 한 줄씩 붙인다.
