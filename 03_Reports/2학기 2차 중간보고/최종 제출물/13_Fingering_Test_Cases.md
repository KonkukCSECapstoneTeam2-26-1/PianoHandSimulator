# 운지법 모듈 테스트 케이스

운지법 모듈 테스트 결과를 뽑기 위한 입력 구성과 지표를 정리한다. 세부 케이스를 다 다루지는 않고, 일반 연주와 과거에 실제로 문제가 났던 지점 위주로 확인한다.

IK 모듈과 다른 점이 하나 있다. 운지법은 **입력이 두 손으로 연주 가능한지**에 결과가 크게 좌우된다. 게임 음악 MIDI는 피아노 연주를 전제로 편곡된 것이 아니어서 애초에 칠 수 없는 구간이 많고, 그런 입력에서 나온 위반은 엔진의 정확도가 아니라 입력의 성질을 반영한다. 그래서 **연주 가능함이 보장된 기준 입력**을 따로 두고, 엔진 자체의 판정은 그쪽으로 한다.

## 1. 일반 입력

실제 곡 MIDI를 일반 연주 케이스로 쓴다.

| 입력 | 위치 | 성격 |
|---|---|---|
| `deb_clai.mid` | `05_Resources/MIDI_Inputs/` | 피아노 악보 기반. 템포 변화 733회, 페달 327회 |
| `Super Mario 64 - Medley.mid` | `05_Resources/MIDI_Inputs/` | 게임 음악이나 음역이 두 손 범위에 들어옴 |
| `test.mid`, `v2_test.mid`, `complex_test.mid` | `05_Resources/MIDI_Inputs/` | 소형 입력. 회귀 확인용 |

## 2. 기준 입력 (연주 가능함이 보장된 입력)

`02_Implementation/01_Fingering/tools/make_reference_corpus.py` 가 생성한다. 각 순간에 한 손이 점유하는 음표 집합이 반드시 유효한 손가락 배정을 갖도록 구성했고, 그 사실을 엔진을 거치지 않고 따로 검증한다. 따라서 **이 입력에서 나온 위반은 전부 엔진 결함**이고 목표값은 0이다.

| 입력 | 겨냥한 것 |
|---|---|
| `ref_01_five_finger` | 고정 5지 포지션 단선율 (기본 동작) |
| `ref_02_block_chords` | 3화음 블록 |
| `ref_03_alberti` | 알베르티 베이스 + 선율 |
| `ref_04_pedal_arpeggio` | 페달로 유지되는 아르페지오 |
| `ref_05_sustained_bass` | 페달 하 지속 베이스 |
| `ref_06_position_shift` | 쉼표로 분리된 포지션 이동 |
| `ref_07_inner_voice` | 페달 없이 손가락으로 유지되는 내성 |
| `ref_08_scale` | 2옥타브 음계 (엄지 넘기기) |

## 3. 코너 케이스

각 케이스는 `piano_fingering_engine.py` 에서 실제로 실패했던 지점을 겨냥한다. 괄호 안은 과거 증상이다.

| # | 케이스 | 입력 예 | 보려는 것 (코드 근거) |
|---|---|---|---|
| 1 | 기준선 | `ref_01_five_finger` | 연주 가능한 입력에서 물리 제약 위반이 0인지 |
| 2 | 템포 변화 | `deb_clai.mid` (Format 1, 템포 트랙 분리, `set_tempo` 733회) | `_build_tempo_map()` 이 전 트랙의 템포를 음표 트랙에 적용하는지. 트랙별로 템포를 따로 추적하면 244초 곡을 387초로 계산한다 (오차 58.7%) |
| 3 | 재타격 | 같은 음을 떼기 전에 다시 누르는 구간 (`deb_clai` 25곳) | `active_notes` 를 pitch별 FIFO 큐로 처리하는지. dict로 두면 선행 음이 덮어써져 사라진다 |
| 4 | `note_off` 누락 | `Queen - Bohemian Rhapsody.mid` (track12) | 트랙이 끝날 때까지 안 닫힌 음표를 종료 시점으로 닫는지 |
| 5 | 페달 | `deb_clai.mid` (CC64 327회, 163구간) | `duration_ms`(소리)와 `key_hold_ms`(손가락 점유)가 분리되는지. 합치면 한 손가락이 서로 다른 건반을 동시에 누른다 (최대 3,000 ms 중첩) |
| 6 | 지속음 교차 | `ref_07_inner_voice`, `ref_05_sustained_bass` | 점유가 후속 화음까지 걸칠 때 순간 단위로 제약을 보는지. 화음 단위로만 보면 같은 데이터에서 위반 3건과 2,552건이 갈린다 |
| 7 | 중복 보이싱 | `wii-wiisports-titlescreen.mid` (1,377화음 중 593화음) | 두 트랙이 같은 음을 동시에 칠 때 하나로 병합하는지. 남기면 같은 건반에 손가락이 둘 배정되어 순서·간격 판정이 연쇄로 깨진다 |
| 8 | 넓은 화음 | 스팬 17반음 초과, 비인접 손가락 쌍 초과 (`[43,50,53,57,60]` 등) | 인접 쌍만 보면 2‑3(6)·3‑5(9)가 통과하면서 2‑5가 15반음이 되는 화음이 빠져나간다. 반대 손 이관·원래 손 복귀·제외 순으로 처리하는지 |
| 9 | 음계 | `ref_08_scale` (2옥타브 다장조) | 엄지 넘기기가 나오는지, 그리고 두 음마다 넘기지는 않는지. 넘기기를 보상하면 `1-4-1-4` 가 최적이 된다 |
| 10 | 88키 범위 밖 | `Queen - Bohemian Rhapsody.mid` (pitch 12, 1개) | 비피아노 트랙이 섞인 MIDI에서 크래시 없이 제외하고 경고하는지 |
| 11 | 연주 불가 편곡 | `Queen - Bohemian Rhapsody.mid` 전체 | 두 손으로 칠 수 없는 구간을 어떻게 처리하는지. 무엇을 왜 버렸는지 보고하는지 |

## 4. 지표

모든 케이스에 같은 지표를 쓴다. 출력은 `results/<곡명>_polyphonic_result.json` 을 기준으로 하고, `02_Implementation/01_Fingering/tools/metrics.py` 로 계산한다. 정의는 `01_Design/10_Fingering_Metrics_Definition.md` 에 있다.

지표는 두 묶음이다. **화음 단위**는 엔진이 자기가 걸기로 한 제약을 지키는지를 보고, **순간 단위**는 물리적으로 옳은지를 본다. 둘의 격차가 설계 결함의 크기를 나타낸다.

| 지표 | 정의 | 기준 |
|---|---|---|
| A1 / A1b 손가락 간격 (화음 단위) | 화음 내 인접·비인접 손가락 쌍이 `MAX_SPAN` 을 넘는 쌍 수 | 0 |
| A2 순서 (화음 단위) | 화음 내 pitch 순서와 손가락 번호 순서의 불일치 | 0 |
| A3 동시 누름 충돌 | 같은 손·같은 손가락의 점유 구간이 겹치는 쌍 수. `key_hold_ms` 기준 | 0 |
| A5 미배정 | `finger == 0` 인 음표 수 | 0 |
| A6 손목 ROM 초과 | `yaw` 35°, `roll` 20° 를 넘는 음표 수 | 0 |
| A7 손 범위 (순간 단위) | 한 순간에 점유 중인 음표 집합의 모든 손가락 쌍이 `MAX_SPAN` 을 넘는 시점 수 | 0 |
| A8 / A8b 중복 (순간 단위) | 한 순간에 같은 손가락 또는 같은 건반이 둘 이상 | 0 |
| A9 순서 (순간 단위) | 점유 집합의 pitch 순서와 손가락 순서 불일치. 엄지는 제외 | 0 |
| 음표 보존율 | 최종 출력 음표 수 ÷ 파싱 음표 수. 제외 사유별 내역 포함 | 입력에 따라 다름 |
| 타이밍 정확도 | mido 템포맵 기준 절대 시각과의 최대 오차 | 1 ms 미만 |
| 손가락 분포 | 1~5번 사용 비율과 균등분포 대비 편차 | 참고값 |
| 처리 시간 | 곡당 소요 | 참고값 |

## 5. 실행 방법

```
cd 02_Implementation/01_Fingering
python tools/run_batch.py --all --metrics
```

곡별 음표 수·제외·점유 단축·미해결 시점·소요 시간·위반 수를 한 표로 낸다. 하드 제약 위반이 있으면 종료 코드 1을 반환한다. 회귀 테스트는 `tests/` 아래 5종을 따로 돌린다.

| 테스트 | 확인 항목 |
|---|---|
| `test_midi_timing.py` | 타이밍 오차와 음표 유실 (MIDI 13곡) |
| `test_keyboard_geometry.py` | 건반 좌표 변환식 |
| `test_metrics.py` | 지표가 위반을 실제로 검출하는지 (위반 주입) |
| `test_required_hold.py` | 페달 기반 필수 점유 구간 |
| `test_reference_corpus.py` | 기준 입력 연주 가능성 + 엔진 위반 0 |

## 6. 결과 정리 방식

- 케이스 × 지표 표 하나로 정리한다.
- 일반 입력과 기준 입력을 나눠 적는다. 기준 입력에서 나온 위반만 엔진 결함으로 읽는다.
- 음표가 제외된 경우 수치만 적지 않고 사유를 함께 적는다 (양손 배정 불가 / 5음 초과 / 88키 범위 밖 / 순간 충돌).
- 해결하지 못한 항목도 빼지 않고 "알려진 한계"로 함께 적는다. 현재 해당하는 것은 다음과 같다.

| 알려진 한계 | 내용 | 후속 |
|---|---|---|
| 연주 불가 입력의 음표 제외 | 양손 어디에도 배정할 수 없는 음표를 버린다. 성부 중요도 순 배정으로 2,525개에서 1,394개까지 줄였으나 남아 있다 | 아르페지오 분산(온셋 미세 분할)으로 추가 복구 |
| 음계 운지 세부 | 엄지 넘기기는 동작하나, 오른손 음계가 표준(`1-2-3-1-2-3-4-5`)과 묶음 구성이 다르다 | 음계 구간 인식 후 시작·종료 손가락 유도 |
| 피아노 트랙 자동 선별 | 요구사항 2.3의 트랙 선별이 미구현이다. 88키 범위 밖 음표만 제외하고 있어, 범위 안의 비피아노 트랙은 그대로 운지 대상이 된다 | GM 프로그램 번호·음역 집중도·노트 수 기준 선별 |
| 손 크기 프리셋 | 요구사항 UC-02의 프리셋이 미구현이다. `MAX_SPAN` 이 단일 값으로 고정되어 있다 | 공유 상수에 배율을 두어 프리셋별로 조정 |
