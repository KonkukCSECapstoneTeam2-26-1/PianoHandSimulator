# 04_Flesh 진행 현황 (발표용 정리) — 곽경민

작성일: 2026-10-29. 수치는 모두 이 프로젝트에서 직접 측정한 값이며, 측정하지 못한 항목은 "미확인"으로 적었다.

## 1. 한 장 요약

- 맡은 부분: MIDI → 운지(01) → IK(02) → **스키닝(03, 이수민) / Flesh(04, 곽경민)** → 렌더. Flesh는 Chaos Flesh(PBD)로 손의 살 변형을 계산한다.
- 지난 보고 이후 한 일: ① Flesh 결과를 수민 님 스키닝에 **실제로 섞는 연결(어댑터)** 구현·검증, ② 승현 님 IK 각도를 **CSV로 받아 애니메이션으로 만드는 경로** 구현·검증, ③ 어댑터 성능 46 ms → 7 ms 개선.
- 지금 가장 큰 문제: **프레임이 약 20 FPS**(목표 60 FPS 미달)이고, 병목은 어댑터가 아니라 게임 스레드의 기본 비용(약 44 ms)이다. 원인은 아직 분리하지 못했다.

## 2. 진행된 사항

### 2.1 Flesh 에셋과 설정 (Dataflow)
- 사면체 메시(정점 5,688개)를 만들고 손 뼈에 바인딩. 렌더 메시 `SKM_MH_Hand_R_Dense`(74,186 정점)를 `GenerateSurfaceBindings`로 사면체에 묶었다(고아·재부모 정점 없음).
- 부위별 바인딩(`BindMask`로 손가락만 뼈에 고정)을 구성하고 테스트 레벨 `L_FleshTest`에서 검증했다.
- 비교용으로 Flesh 결과를 Geometry Cache(126 MB)로 구웠다. GitHub 100 MB 한도 때문에 `.gitignore`로 제외(저장소에 없음, 필요하면 Dataflow에서 다시 구움).

### 2.2 "Flesh가 뒤늦게 따라온다" 조사 결과
- 원인에서 제외된 것: 솔버 타이밍, 중력, 바인딩 방식(전체/부위별).
- 확인된 것: 정지 자세에서도 Flesh가 LBS보다 **두껍고 부피를 보존하는 형태**이며, 주먹을 쥘 때 가장 안쪽 살이 **지글거린다**(자기충돌 없음 → 안쪽이 구겨짐).
- 수민 님 파이프라인은 순수 LBS가 아니다(DQS/LBS + Implicit Skinning + 부피 팽창 + 관절 주름 + 텐션 + UV 이음매 용접). 그래서 "LBS 대비 Flesh" 사진 비교는 수민 님 결과와 Flesh의 비교로 정리했다.

### 2.3 수민 님 스키닝과의 통합 (어댑터)
2026-10-27 합의: ① 스키닝 직후에 Flesh를 섞음(슬라이더), ② 이음매는 필요할 때만 수민 방식, ③ 입력 구멍은 곽경민 별도 파일·수민 님은 읽는 몇 줄, ④ Flesh를 쓸 때는 손 크기 조절(Phase 5)을 끔.

구현한 것(전부 `Source/pianohand_simulator/Flesh/`와 `Shaders/Private/PianoHandFleshBlend.usf`):
- `UPianoHandFleshInputComponent`: Flesh 표면 위치를 매 프레임 읽어 렌더 스레드로 전달. 속성 `Blend`(0 = 스키닝만, 1 = Flesh만), `Enabled`, `Fast Read`, `Debug Lift Cm`(동작 확인용).
- 컴퓨트 셰이더 `lerp(스키닝, Flesh, Blend)`를 수민 님 디포머의 스키닝 패스 **바로 뒤**에 1줄 호출로 연결. 수민 님 파일에는 `include` 1줄 + 호출 1줄만 추가했다(Flesh 데이터가 없으면 아무 일도 하지 않음).

검증 결과:

| 확인 항목 | 결과 |
|---|---|
| Flesh가 돌려주는 정점 수 vs 렌더 메시 정점 수 | 74,186 = 74,186 (일치) |
| 정점 순서·좌표계 (휴지 자세 편차) | 평균 0.27 cm, 최대 0.35 cm → **이음매 매핑 불필요** |
| 렌더 패스 실행 | 호출 301회 중 301회 실행(데이터 없음·정점 수 불일치 0) |
| 좌표 변환 | 필요 없음(변환 전후 편차 동일) |

### 2.4 성능 개선 (어댑터)
- 문제: Flesh의 `GetGeometryCachePositions`가 호출마다 바인딩을 다시 읽고 7만 정점을 한 스레드에서 계산 → **46 ms/프레임**.
- 조치: 바인딩·평가기를 한 번만 만들고 정점 계산을 모든 코어로 병렬화(엔진 함수와 같은 수식).
- 결과: **약 7 ms/프레임**(약 6.6배 단축). 실패하면 엔진 함수로 자동 복귀하는 안전장치와 `Fast Read` 끄기 옵션이 있다.

### 2.5 IK 연동 (승현 님 ↔ 곽경민)
- 각도 인계 형식 정의(`IK_Handoff_Format.md`): `joints.csv`(`frame,time_ms,bone,flex_deg,abd_deg,twist_deg`, 오른손 15행/프레임, 30 FPS), `wrist.csv`.
- 검증기 `check_ik_csv.py`, 임포터 `import_ik_csv_to_anim.py`(AnimSequence 생성) 구현.
- 승현 님이 반영한 것: CSV 내보내기(60 Hz 내부 계산 → 30 FPS 기록), MetaHuman 실측 마디 길이, 엄지 뿌리를 손목 쪽 4.5 cm로 이동·타건 지점 조정.
- 실제 곡으로 확인: `deb_clai`(248 초, 7,447 프레임) 내보내기 **4 초**(Release), 검증기 `RESULT: OK`, `A_IK_DebClai` 애니메이션 생성·저장 성공.
- 이 PC에서는 Vulkan SDK를 설치해 IK 프로그램을 직접 빌드·실행할 수 있게 했다(소스는 수정하지 않음).

## 3. 문제가 있는 부분

### 3.1 성능 (가장 큰 문제)
| 상태 | Frame | Game(CPU) | GPU | FPS |
|---|---|---|---|---|
| 어댑터 끔 | 44.5 ms | 44.3 ms | 4.6 ms | 약 22 |
| 어댑터 켬(수정 전) | 91 ms | — | — | 약 11 |
| 어댑터 켬(수정 후, 정상 상태) | 약 51 ms | 약 51 ms | 약 3.7 ms | 약 20 |

- GPU는 한가하고 **게임 스레드가 병목**. 60 FPS(16.7 ms)에는 기본 비용 44 ms를 약 1/3로 줄여야 한다.
- 44 ms가 Flesh 시뮬레이션인지, 두 손(342본 × 2)의 애니메이션 평가인지, 에디터 PIE 오버헤드인지는 **아직 분리하지 못함**. `stat game`으로는 컴포넌트 틱 세부가 안 보인다.
- 측정은 모두 에디터 PIE 기준이며 Standalone/패키지 빌드는 미측정.

### 3.2 IK 각도·손 모양 문제 (추후 수정 예정)
IK가 내보낸 각도로 만든 손 모양이 자연스럽지 않다. 아래는 **알려진 문제이며 추후 수정 예정**이고, 이번 Flesh·어댑터 작업의 결함이 아니다. 운지법(01) 결과나 IK(02)의 규약에서 비롯된 것으로 보이나 어느 쪽인지는 아직 가리지 않았다.

- **손 모양 이상**: 엄지가 상시 찌그러져 보이고, 손가락이 부자연스럽게 꺾인다. IK 프로그램의 작대기 화면에서도 같은 이상이 보였다.
- **엄지 각도**: `thumb_01` 굴곡이 −50°~41°로 다른 손가락과 범위가 크게 다름.
- **급점프**: 곡 중 거의 모든 관절에서 한 프레임에 40~120° 점프(예: `middle_02_r` 123°).
- **운지법 이상으로 인한 손 모양 문제**: 운지 결과(어느 손가락이 어느 건반을 누르는지)가 부자연스러우면 IK가 무리한 자세를 만들어 손 모양이 깨진다. 운지법 쪽 개선이 필요한지는 미확인.

세부 관찰:
- 프레임 0(시작 자세)에서 중간 마디가 84~97° 굽은 채 시작, 뿌리 마디 −20°(엄지 −37.8°), 끝 마디 32°. 기본 굽힘이 각도에 포함된 것인지 확인 필요.
- `*_metacarpal_r` 4개 본은 데이터가 없어 휴지 자세로 남음. 원위 마디 길이(엄지·중지·약지)와 엄지 뿌리 4.5 cm는 추정값. 손바닥(7.2~8.1 cm)이 IK에 없음. 승현 님 보고 기준 엄지 오차 1 cm 이상 비율 41.2%(검은 건반 56.2%).
- IK가 손목 회전을 내보내지 않음(`yaw/pitch/roll` = 0).

### 3.3 Flesh 자체의 모양
- 정지 자세에서도 LBS보다 두껍다(평균 편차 약 0.3 cm).
- 주먹을 쥘 때 가장 안쪽 살이 지글거림(자기충돌 없음). 댐핑 0.1 → 0.5, 팽창 0.5 → 0, 비압축성 조정은 **아직 시도하지 않음**.
- IK의 급점프 구간에서 Flesh가 안정적으로 따라오는지는 **미확인**.

### 3.4 통합·환경
- `L_FleshTest`에는 수민 님 디포머가 저장돼 있지 않아 스크립트(`attach_skin_deformer_flesh.py`)로 붙인다. 수민 님 데모 설정과 일부(모드 등) 다를 수 있음.
- 어댑터는 한 프레임 지연될 수 있음(게임 → 렌더 스레드 전달).
- Flesh 표면과 Geometry Cache 액터가 보이면 겹쳐 보이므로 최종 장면에서는 숨겨야 함.
- 재생 시 큰 구체(`DefaultPawn0`), 어두운 화면, 약간 뿌연 화질은 원인 미확정(조명 모빌리티/자동 노출/Lumen 추정, 확인 안 됨).
- 에디터 종료 시 크래시(저장 후 콘텐츠 검증 중 엔진 쪽 접근 오류, 데이터 손실 없음).

## 4. 개선해야 하는 사항 (우선순위 순)

1. **성능 병목 분리**: ① Flesh 액터 끄고 측정, ② 수민 님 디포머 떼고 측정, ③ Standalone Game에서 측정. 결과에 따라 Flesh 솔버 가볍게(사면체·반복 수·시간 간격) 또는 수민 님과 상의.
2. **IK 각도·손 모양 수정**(추후 수정 예정, 3.2): 급점프 평활화, 시작 자세/엄지 각도 규약 확인, 손바닥 반영, 운지법 이상 여부 점검.
3. **Flesh 안정화**: 지글거림·두께 튜닝 후 캐시 재생성, 빠른 동작 구간에서 안정성 확인.
4. **수민 님 설정과 맞추기**: 최종 레벨에 디포머와 세부 설정이 저장되도록 정리, Phase 5 비율 끄기 확인.
5. **통합 장면 정리**: 구체·조명·노출 문제 해결, Flesh 가시 메시 숨김.
6. 실제 효과 평가: `Blend` 0/0.5/1 비교 사진·영상으로 Flesh를 섞었을 때의 이득(살의 눌림·부피) 정리.

## 5. 이번 주 일정과 남은 일
- 통합 주간 2026-10-26 ~ 11-01. 남은 일: 위 1~5번과 발표 자료.
- IK 각도·손 모양 문제(3.2): 추후 수정 예정(승현 님 IK, 필요하면 정근녕 님 운지법).
- 수민 님: 스키닝 파일에 2줄 추가가 커밋되었음을 알렸다.

## 6. 재현 방법 (발표 시연용)
1. IK 각도 만들기: 환경 변수 `PH_EXPORT_CSV=1`, `PH_EXPORT_ONLY=1`로 IK 프로그램(Release) 실행 → `ik_joints.csv`, `ik_wrist.csv`.
2. 애니메이션 만들기: 에디터 Output Log(Cmd → Python)에서 `Scripts/run_ik_import_deb_clai.py` 실행 → `A_IK_DebClai`.
3. `L_FleshTest`: `PH_MH_Hand`(수민 손, 디포머)와 `HandFleshAsset`(Flesh)에 같은 애니메이션 지정, `Piano Hand Flesh Input`의 `Skinned Actor = PH_MH_Hand`, `Blend` 조절 후 재생.
4. Output Log에서 `[FleshInput]`로 정점 수·편차·렌더 패스·프레임 시간 확인.
