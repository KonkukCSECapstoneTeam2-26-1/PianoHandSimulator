**주요 활동**: 2차 중간발표 수행 및 제출 문서 작성, 모듈별 측정값 통합

**세부 내용**:
10월 30일 2차 중간발표를 진행하였음. 발표에 앞서 제출 문서 4종(요구사항 분석서, 프로젝트 설계서,
운지법·스키닝 테스트 케이스)과 발표자료를 작성하였음. 발표 시간이 10분으로 정해져 29장 중 17장만
사용하고 나머지는 숨김 처리하여 질의응답 시에만 띄우도록 구성하였음.

각 파트의 측정값을 받아 문서에 반영하는 과정에서, 기존에 추정으로 적어 두었던 내용 세 건이
실제와 달랐음을 확인하고 정정하였음.
첫째, IK 수렴 판정의 허용 오차 0.01을 cm로 오인하고 있었으나 IK 내부 단위(약 0.05 cm)였으며,
이 때문에 "수렴 실패 60.7%"를 작은 문제로 읽을 뻔하였음. 실제로 수렴하지 못한 풀이의 남은 오차
중앙값은 1.4 cm였음.
둘째, 손목 회전값 유실 건에 대해 "롤을 반영하면 해결된다"고 적었으나, 반영 실험 결과 롤 단독으로는
효과가 없었고 요(yaw)를 함께 넣어야 엄지-흑건 오차가 1.54 cm에서 1.10 cm로 감소하였음.
셋째, Chaos Flesh의 손끝 어긋남을 "지연이 아니라 형태 차이"로 추정하였으나, 측정 결과 정지에
가까울 때는 형태 차이(0.2~0.7 cm), 손끝이 10 cm/s 이상 움직일 때는 약 한 프레임 지연(1.3~4.6 cm)으로
두 가지가 섞여 있었음.
또한 설계서에 기재한 "2차 베지어 곡선으로 손목 궤적 생성"이 코드와 다름을 확인하고
지수 감쇠 보간 방식으로 정정하였음.

**향후 활동**:

### 한승현 (IK)

**주요 활동**: 관절 각도 CSV 인계 경로 구현 · 계측 빌드로 IK 품질 측정

**세부 내용**:
IK 결과를 다른 파트가 쓸 수 있도록 관절 각도를 CSV로 내보내는 경로를 구현함. 내부 계산은 60 Hz로
하되 기록은 30 FPS로 맞추었고, 긴 곡에서도 상태를 알 수 있게 진행률을 출력하도록 함.
손가락 마디 길이를 MetaHuman 손 실측값으로 변경하였고, 엄지 뿌리를 CMC 위치로 옮긴 뒤 엄지의
타건 지점을 건반 앞쪽으로 조정함.

또한 저장소 코드와 별개로 계측 코드를 넣은 빌드를 만들어 IK 품질을 수치로 측정함. 기존에
`joints.csv` 만으로 손끝 오차와 반복 수를 계산할 수 있다고 보았으나, 반복 수는 출력되지 않고
오차 계산에는 손목 위치·건반 좌표·음표 데이터가 함께 필요하여 IK 쪽에 계측을 넣는 방식으로 변경함.
일반 3곡 기준(오른손, 타건 150 ms 이후) 손끝–건반 오차는 평균 0.45 cm, 최대 10.66 cm,
1 cm 이상이 5.1%였음. 반복은 평균 31.0회이며 40회 안에 수렴하지 못한 프레임이 60.7%였음.
관절 제한은 거의 항상 DIP 최대 굴곡(32°)과 MCP 최대 신전(20°)에서 걸려, 목표점이 손가락 도달
범위의 끝에 놓인다는 것을 확인함. 인접 프레임 간 각도 변화 최대값은 39.1°였고, 달빛에서는
123.5°까지 나오며 25°를 넘는 점프가 903회 발생함. 원인은 매 프레임 관절을 0°로 초기화한 뒤
다시 푸는 구조에 있음.

손목 회전 반영 실험도 수행함. 현재 IK는 운지법 CSV를 13번째 열부터 파싱하여 `WristYawDeg`·
`WristRollDeg` 를 읽지 않으며 출력도 0으로 고정되어 있음. 반영해 본 결과 롤 단독으로는 효과가
없었고(±12°를 적용해도 엄지 뿌리가 약 0.4 cm만 상승), 요를 함께 넣었을 때 엄지–흑건 오차가
1.54 cm에서 1.10 cm로 감소함.

**향후 활동**:
손가락 마디 길이와 기본 굽힘 파라미터를 재검토할 예정. 프레임 0에서 중간 마디가 84~97° 굽은 채
시작하는 현상이 기본 굽힘이 각도에 포함되어 생긴 것인지 확인이 필요함. 요(yaw)의 부호는 운지법
엔진 코드를 보고 추론한 것이라 운지법 파트와 확인이 필요함.

### 곽경민 (Chaos Flesh)

**주요 활동**: Flesh–스키닝 연동 · 손끝 어긋남 측정

**세부 내용**:
Chaos Flesh의 살 변형 결과를 이수민 님 스키닝 파이프라인에 섞는 어댑터를 구현함. Flesh가 계산한
표면 위치(74,186 정점)를 스키닝 직후에 Blend 값으로 섞으며, 정점 수·순서 일치를 로그로 확인했고
(휴지 자세 편차 평균 0.27 cm) 렌더 패스가 매 프레임 실행됨을 확인함. Flesh 위치 읽기가 프레임당
46 ms였으나 바인딩 평가기 재사용과 병렬 계산으로 약 7 ms로 줄였고, PIE 첫 프레임 접근 위반도
수정함. 손끝 정점을 잡아 Flesh와 스켈레탈 메시(LBS)의 거리를 수치로 측정한 결과, 정지 시
0.2~0.7 cm는 형태 차이(Flesh가 부피를 유지해 더 두꺼움)이고, 움직일 때 1.3~4.6 cm는 약 한 프레임
분량의 시간 지연(Flesh가 이동 반대 방향으로 뒤처짐)임을 확인함. 손가락을 뼈에 묶으면 정지 시
어긋남이 30~40% 줄지만 움직일 때의 지연은 그대로였음. 또한 한승현 님 IK의 관절 각도를 CSV로
받아 애니메이션으로 만드는 경로(형식, 검증기, 임포터)를 구현하고, 실제 곡(deb_clai, 248초,
7,447프레임)으로 내보내기부터 애니메이션 생성까지 확인함.

**문제 및 향후 활동**:
- 프레임이 약 20 FPS로 목표(60 FPS)에 못 미침. 병목은 게임 스레드 기본 비용(약 44 ms)이며
  원인(Flesh 시뮬레이션·애니메이션 평가·에디터 오버헤드)을 아직 못 가름. 항목별로 끄고 측정할 예정.
- 움직일 때의 시간 지연 원인(Flesh가 뼈 자세를 한 프레임 늦게 쓰는지 등)은 가르지 못함.
  Play Rate 0 정지 측정과 지연의 ms 환산이 남음.
- IK 각도로 만든 손 모양이 부자연스러움(엄지 찌그러짐, 급점프 등). 추후 수정 예정.
- 주먹 쥘 때 안쪽 살 지글거림과 두께 차이 튜닝 예정.

## 지도교수 피드백 (10/30 2차 중간발표)

### 1. 코스트 함수의 결합 방식 — 가산(加算)의 한계

발표 중 두 차례, 마무리에서 한 차례 더 언급된 가장 비중 있는 지적임.

> 절대 위반해서는 안 되는 제약을 가산 코스트에 섞으면, 다른 항이 낮아질 때 전체 합이 작아져
> 위반이 선택될 수 있음. max를 쓰는 방법, 곱을 쓰는 방법 등 여러 결합 방식을 비교해 볼 필요가 있음.
> 또는 제약을 먼저 걸러 낸 뒤 남은 후보에 대해서만 코스트로 고르는 방식이 있음.

**현재 코드 확인 결과, 지적이 정확하였음.**

운지법 엔진의 동적 계획법은 하드 제약을 후보에서 배제하지 않고 큰 패널티를 더하는 방식으로
다루고 있음. 후보 생성 함수 `get_combinations(k)` 는 손가락 조합 C(5,k)를 제약 검사 없이 전부
반환하며, 제약 위반은 아래 상수들이 가산되는 형태로 처리됨.

| 상수 | 값 | 의미 |
|---|---|---|
| `OCCUPANCY_SPAN_PENALTY` | 5000 | 순간 손 범위 초과 |
| `OCCUPANCY_FINGER_PENALTY` | 4000 | 한 손가락이 두 건반을 동시에 |
| `OCCUPANCY_ORDER_PENALTY` | 1500 | 음높이 순서와 손가락 순서 역전 |

이 값들은 선호도에 해당하는 항(성부별 보정 −12 ~ +20, 순차 진행 보상 −20 등)과 **같은 스칼라에
더해짐**. 코드 전체에 `penalty +=` 지점이 19곳 있음.

특히 `is_chord_playable()` 함수의 주석에 해당 실패 양상이 이미 기록되어 있었음.

> "그 경우 DP는 +5000 패널티를 물고 물리적으로 불가능한 운지를 출력한다."

이 함수는 화음 분리 단계에서 전처리로만 쓰이고 DP 내부 후보 생성에는 쓰이지 않음.
즉 지도교수가 지적한 구조가 코드에 그대로 남아 있었음.

**추가로 확인한 것**:
빔 가지치기(`DP_BEAM_WIDTH = 120`)도 같은 스칼라로 정렬함. 화음마다 상위 120개 상태만 남기는데,
위반이 없는 상태가 선호도 때문에 순위에서 밀리면 그 자리에서 잘려 나가고 이후 복구되지 않음.
즉 "나쁜 쪽이 선택될 수 있다"에 더해 "좋은 쪽이 후보에서 사라진다"는 경로가 하나 더 있었음.

또한 현재 21곡에서 순간 단위 위반이 0건인 것은 DP가 잘 골라서가 아니라, DP 뒤에 붙인 사후 해소와
화음 분리가 남은 위반을 치우기 때문임. 따라서 현재 지표로는 코스트 구조의 품질을 볼 수 없으며,
사후 해소를 끄고 **DP 직후 위반 수**를 재야 비교가 가능함.

**측정 결과**:
고치기 전에 먼저 쟀음. 저장소 코드는 수정하지 않고 엔진 소스에 카운터만 끼운 사본을 돌렸음.

| | 기준 코퍼스 8곡 | 실곡 13곡 |
|---|---|---|
| DP 직후 위반 시점 | **0** | 2,384 |
| 사후 해소 후 | 0 | 0 |
| 가지치기로 버린 상태 | 5,300 | 202,780 |
| 그중 위반이 없던 것 | 455 (8.6%) | 2,922 (1.4%) |

두 가지가 갈렸음.
첫째, **위반이 선호도와 교환되는 현상은 관측되지 않았음.** 연주 가능함이 보장된 기준 코퍼스에서
DP 직후 위반이 0이므로, 입력이 실제로 칠 수 있는 곡이면 현행 가산 구조도 위반을 고르지 않음.
실곡의 2,384건은 입력이 두 손으로 칠 수 없는 구간이라는 기존 측정(81.6%)과 일치함.
둘째, **가지치기에서 좋은 상태가 사라지는 현상은 관측되었음.** `ref_04_pedal_arpeggio` 는 화음의
53.3%에서 빔이 포화되며, 그 과정에서 위반 없는 상태 455개를 버리면서 위반 있는 상태 1,247개를
남겼음. 연주 가능한 입력에서도 일어나지만, 이 곡의 최종 위반은 0이므로 결과를 바꾸지는 않았음.

**후속 계획**:
측정 결과에 따라 계획을 줄였음. 지적은 구조적으로 타당하나 **현재 품질 문제의 원인은 아니므로**,
전면 재설계를 밀어붙일 근거가 없음.
1. 빔 가지치기 정렬 기준을 `(위반 수, 선호도 합)` 으로 변경 — 관측된 문제이고 변경 범위가 작음
2. 회귀 테스트 5종과 21곡 재처리로 부작용 확인
3. 교환 현상이 재현되는 기준 입력을 추가 — 현재 코퍼스는 짧고 쉬워 8곡 중 5곡은 빔이 포화조차
   되지 않음. 긴 곡, 포지션 이동이 잦은 곡 등이 필요함
4. 재현된 뒤에 후보 배제·전이 배제·사전식 비교를 구현하고 가산 / max / 곱을 비교 측정

근거 없이 구조를 바꾸면 좋아졌는지 나빠졌는지 말할 수 없으므로, 재현 입력 확보를 앞에 둠.
설계안과 측정 결과는 `01_Design/13_Cost_Function_Design.md` 에 정리함.

### 2. IK 결과와 모델 간의 괴리

> 테스트 툴에서 보이는 손 모양과 실제 모델에 적용했을 때의 손 모양이 다름.
> IK가 더 많이 굽어지는 것으로 보임. 손가락 길이와 마디 파라미터를 다시 볼 것.

이 지적은 발표 전 측정값과 일치함. 손가락 마디 길이를 MetaHuman 실측값으로 변경한 뒤 소지 오차가
35%에서 57%로 증가하였고, 프레임 0에서 중간 마디가 84~97° 굽은 채 시작하는 현상이 확인되어 있음.
기본 굽힘이 각도에 포함된 것인지 확인이 필요한 상태임.

### 3. Chaos Flesh 지연

> 덩어리가 지연되어 따라오는 현상이 육안으로 확인됨.

측정값과 일치함(손끝 10 cm/s 이상에서 1.3~4.6 cm, 약 한 프레임 분량).
