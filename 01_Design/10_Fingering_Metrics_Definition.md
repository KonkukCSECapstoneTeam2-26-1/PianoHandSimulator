## 0. 본 문서의 목적과 전제

1학기 보고서에는 "실제 피아니스트와 85% 이상 일치", "비정상 화음 스팬 0.0%"와 같은
수치가 기재되어 있으나, **그 수치의 측정 방법을 정의한 코드나 문서가 존재하지 않았다.**
본 문서는 그 공백을 메우기 위해, 운지법 엔진의 출력 품질을 **재현 가능한 방식으로**
측정하는 지표를 정의한다.

### 0.1 측정 가능 / 측정 불가의 구분

| 구분 | 내용 | 본 도구 |
|------|------|---------|
| **정답 없이 측정 가능** | 물리·해부학 제약 위반, 분포 통계, 엔진 자체 규칙과의 자기일관성 | **측정함 (본 문서 §2, §3)** |
| **정답 데이터 필요** | 실제 피아니스트 운지와의 일치율, 연주 자연스러움에 대한 주관 평가 | **측정 불가 (§4)** |

> **중요**: 본 도구는 "일치율"을 산출하지 않는다. 기준(정답) 운지 데이터가 없는 상태에서
> 일치율을 추정해 보고하는 것은 근거 없는 수치 생성에 해당한다. 측정에 필요한 조건은 §4에 기술한다.

### 0.2 입력과 실행

```
입력 : 02_Implementation/01_Fingering/results/*_polyphonic_result.json
       (엔진 출력 그대로. 음표 객체 배열)

실행 : cd 02_Implementation/01_Fingering
       python tools/metrics.py results/deb_clai_polyphonic_result.json   # 단일 파일
       python tools/metrics.py                                           # results/ 전체 순회
       (Windows cp949 콘솔에서는 PYTHONIOENCODING=utf-8 필요)

종료 코드 : [A] 하드 제약 위반이 하나라도 있으면 1, 모두 0건이면 0
            (파일 로드 실패 등 측정 자체가 불가하면 2)
```

### 0.3 설계 원칙

| 원칙 | 구현 방식 |
|------|----------|
| 상수 중복 금지 | `MAX_SPAN`, `WRIST_ROM`은 `piano_fingering_engine`에서 **import**. 복제하지 않는다. 엔진 상수가 바뀌면 지표 판정도 자동으로 따라간다. |
| 스키마 변화 내성 | 미지의 필드(`target_x_mm` 등)는 무시하고 보존. 필수 필드 결손·타입 이상·`dict`가 아닌 원소도 예외 없이 기본값 처리. |
| 측정 가능성 검증 | "위반 0건"이 계산 미수행 때문이 아님을 보이기 위해, 위반을 주입한 소형 샘플로 각 지표의 검출력을 테스트한다(§5). |

### 0.4 공통 전제: 화음 그룹 재구성

지표 다수는 "화음" 단위로 정의된다. 결과 JSON에는 화음 ID가 없으므로 엔진과 **동일한 규칙**으로
재구성한다.

```
같은 손(hand)의 음표를 start_ms 오름차순 정렬 후,
그룹 첫 음표와의 start_ms 차이가 30ms 미만인 음표를 같은 화음으로 묶고
pitch 오름차순 정렬한다.   (CHORD_WINDOW_MS = 30.0)
```

근거: 엔진 `parse_midi_to_hand_chords()`의 `start_ms - curr_group[0].start_ms < 30`,
및 `split_wide_chords_between_hands()`의 merge 조건과 동일.

**한계**: 엔진 내부의 화음 경계를 100% 복원하는 것은 아니다. 엔진은 split→merge를
반복하면서 그룹 기준 음표가 바뀔 수 있어, 경계 근처(≈30ms)의 음표 1~2개가 다른 화음으로
귀속될 가능성이 있다. 이 때문에 화음 단위 지표(A1, A2, A4, B8)는 **원리적으로 재구성 오차를
포함**한다. 근본 해결책은 엔진이 출력 JSON에 `chord_id`를 포함시키는 것이다(§6 개선 과제).

## 2. [A] 물리 제약 위반 — 하드 제약

설계 명세서 `02_Fingering_Design_Spec.md`가 해부학적 하드 제약으로 규정한 항목.
**정상 출력이라면 모두 0건이어야 하며, 1건이라도 있으면 FAIL**이다.

| # | 지표 | 정의 / 계산식 | 판정 기준 | 한계 |
|---|------|--------------|----------|------|
| **A1** | MAX_SPAN 초과 (인접 쌍) | 같은 손·같은 화음 내에서 pitch 오름차순 **인접** 음표쌍 `(a,b)`에 대해 `b.pitch − a.pitch > MAX_SPAN[sorted(a.finger, b.finger)]`인 쌍 수. 미등재 쌍의 한계는 엔진과 동일하게 12반음. 분모는 평가된 인접쌍 총수. | `0건` → PASS | 엔진 DP 비용 함수와 **동일한 검사 범위**(인접 쌍만). `finger==0`(A5)이거나 두 손가락이 같은(A4) 쌍은 평가에서 제외한다. |
| **A1b** | MAX_SPAN 초과 (비인접 쌍) | 같은 화음에서 pitch 순으로 **하나 이상 건너뛴** 쌍 `(i, j≥i+2)`에 대해 동일한 판정. | `0건` → PASS | **엔진의 사각지대를 겨냥한 지표다.** 엔진은 인접 쌍만 검사하므로, 인접 쌍이 모두 한계 내여도 손 전체로는 벌릴 수 없는 화음이 통과한다. 예: `[p56:f2, p62:f3, p71:f5]` — 인접 2‑3 gap 6(≤6), 3‑5 gap 9(≤10)는 통과하지만 비인접 2‑5 gap 15 > 12로 **물리적으로 연주 불가**. 요구 지표 목록에는 없던 항목이나, 연주 가능성에 직결되므로 하드 제약으로 분류하고 종료 코드에 반영한다. |
| **A2** | Monotonicity 위반 | 같은 화음 내 pitch 오름차순 인접쌍에 대해, 오른손은 `b.finger > a.finger`, 왼손은 `b.finger < a.finger`를 요구. 불만족 쌍 수. | `0건` → PASS | 같은 pitch가 한 화음에 중복 존재하면(동음 재타격) 순서 판정이 모호하다. 현재는 일반 쌍과 동일하게 위반으로 센다. |
| **A3** | 동시 누름 충돌 | 같은 손·같은 손가락인 두 음표 `(prev, cur)` (`prev.start ≤ cur.start`, **서로 다른 화음**)에 대해 `prev.start + prev.key_hold − cur.start > 1.0ms`인 쌍 수. | `0건` → PASS | 같은 화음 내 중복은 A4에서 집계하므로 제외한다. **`duration_ms`가 아니라 `key_hold_ms`를 쓴다** — `duration_ms`는 Sustain 페달로 늘어난 *소리*의 지속이므로 중첩이 정상이며, 이를 쓰면 페달로 유지된 음을 전부 위반으로 오검출한다(드뷔시 '달빛'에서 101건 오검출). `key_hold_ms`가 없는 구버전 JSON은 `duration_ms`로 폴백한다. 임계 `1.0ms`의 근거는 아래 **A3b** 참조. |
| **A3b** | 경계 접촉 (참고) | 위 중첩량이 `0 < overlap ≤ 1.0ms`인 쌍 수. **충돌로 세지 않는다.** | 판정 없음(참고) | 결과 JSON은 `start_ms`/`key_hold_ms`를 소수 2자리로 기록하므로, "앞 음을 떼는 순간 뒤 음을 누르는" 정상적 레가토 경계에서 0.01ms 수준의 **가짜 중첩**이 발생한다. 이를 충돌과 분리하기 위한 지표다. 반대로 1ms 이내의 **진짜** 충돌은 놓친다(물리적으로 무의미한 수준). |
| **A4** | 화음 내 손가락 중복 | 한 화음에서 `finger` 값별 등장 횟수 `c`에 대해 `Σ max(0, c−1)`. (중복 발생 화음 수도 함께 보고) | `0건` → PASS | `finger==0`은 제외(A5에서 집계). |
| **A5** | 미배정 | `finger == 0`인 음표 수 / 전체 음표 수. `finger` 필드 결손·비정수도 0으로 간주. | `0건` → PASS | 엔진의 `_trim_chord()`는 6음 이상 화음을 5음으로 줄이는데, 줄여낸 음표는 `hand_chords`에 남아 JSON에 기록되면서 `finger=0`을 유지한다. A5는 이 경로를 검출하기 위한 지표다. |
| **A6** | ROM 초과 | `abs(wrist_yaw_deg) > WRIST_ROM["yaw_max"]`(35°) 음표 수, `abs(wrist_roll_deg) > WRIST_ROM["roll_max"]`(20°) 음표 수. 각각 별도 행으로 보고. | 각 `0건` → PASS | 엔진이 출력 단계에서 `clamp`하므로 구조상 위반이 나오기 어렵다. 즉 A6는 **엔진이 클램프를 빠뜨리지 않았는지에 대한 회귀 감시** 성격이며, "클램프에 걸려 각도가 포화된 음표 수"(진짜 품질 문제)는 측정하지 않는다. |

## 3. [B] 분포·품질 지표 — 참고값

**절대적 합격 기준이 없는** 지표다. PASS/FAIL로 판정하지 않으며, 엔진 수정 전후 비교나
곡 간 비교에 사용한다. 수치 하나만 떼어 "품질 85%" 식으로 인용해서는 안 된다.

| # | 지표 | 정의 / 계산식 | 해석 | 한계 |
|---|------|--------------|------|------|
| **B7** | 손가락 사용 분포 | `finger∈{1..5}`별 비율(%). 추가로 **균등분포 대비 최대 편차**(`max|pᵢ − 20%|`, 단위 pp)와 **총변동거리** `TVD = ½Σ|pᵢ − 0.2|` (0=완전균등, 0.8=한 손가락 집중). | 특정 손가락 쏠림 탐지 | **균등분포는 정답이 아니다.** 실제 연주에서 4번(약지) 사용률은 보통 낮다. 따라서 TVD가 0에 가깝다는 것이 "좋다"는 뜻은 아니며, 비정상적 편중을 찾는 용도로만 쓴다. |
| **B8** | 화음 통계 | 화음 수, 평균 span(전체 / 2음 이상 화음 각각), 최대 span, `span > 17반음` 화음 수, 최대 동시 발음 수, 단음 화음 비율(%). span = 화음 최고음 − 최저음. | 입력 난이도와 분리기 동작 확인 | 단음이 다수면 "평균 span"이 0쪽으로 희석되므로 **2음 이상 화음 평균을 함께** 본다. `span > 17`과 `최대 동시 발음 > 5`는 사실상 하드 제약이지만, 엔진 `split_wide_chords_between_hands()`/`_trim_chord()`가 구조적으로 보장하는 값이므로 B에 배치하고 참고 판정만 표시한다. |
| **B9** | 단음 연속 같은 손가락 반복 | 같은 손에서 연속한 두 화음이 모두 단음이고, `pitch`가 다르며(동음 제외), `finger`가 같은 전환 수 / 단음→단음 전환 총수. | 낮을수록 양호 | 엔진 `ArpeggioRolling`의 `+60` 조건과 동일 규칙이므로 **엔진 자기일관성 점검**이다. 느린 악구에서는 같은 손가락 반복이 실제로 자연스러울 수 있어, 0이 최적이라는 보장은 없다. |
| **B10** | 아르페지오 방향성 불일치 | 단음→단음 전환(`pitch` 변화 ≠ 0, 손가락 변화 ≠ 0)에서 — 오른손: `상행 AND finger 감소` 또는 `하행 AND finger 증가`; 왼손: `상행 AND finger 증가` 또는 `하행 AND finger 감소` — 인 전환 수 / 전환 총수. | 낮을수록 양호 | 엔진 `ArpeggioRolling`의 `+35` 조건과 동일. **단, 엄지 넘기기(thumb-under)는 정상 연주법인데도 이 규칙에서는 불일치로 계수된다.** 따라서 B10의 잔존 건수 상당 부분은 결함이 아닐 수 있다. 스케일 구간 판별 후 thumb-under를 면제하는 개선이 필요하다(§6). |
| **B11** | 손 분리 품질 | ① 왼손/오른손 pitch 최소~최대 범위. ② **중첩 폭** = `max(0, 왼손최고음 − 오른손최저음)` (반음). ③ **교차 건수** = 시작 시각 차가 30ms 미만인 (왼손 화음, 오른손 화음) 쌍 중 `왼손최고음 > 오른손최저음`인 쌍 수 / 비교된 쌍 총수. | 중첩·교차가 작을수록 분리가 명확 | 중첩 폭은 **곡 전체 최대치 기준**이라 단 한 번의 극단적 패시지에도 커진다(상시 상태가 아님). 교차는 **동시 온셋 화음쌍만** 비교하므로, 앞서 눌러 유지 중인 음과의 교차는 놓친다. 또한 손 교차는 실제 피아노 연주에 존재하는 기법이므로 **그 자체가 오류는 아니다.** |
| **B12** | 흑건 1·5번 배정 | 흑건 음표 중 `finger==1` 비율, `finger==5` 비율, 두 비율의 합. 흑건 음표 비율도 함께 보고. | 낮을수록 양호 | 엔진 `BlackKeyPenalty`(1번 +25, 5번 +10)와 같은 선호를 측정한다. 조성에 따라 흑건 비중이 크게 달라지므로(예: Db장조 곡은 흑건 비율 70%대) **곡 간 직접 비교는 부적절**하다. 불가피하게 1·5번을 써야 하는 구간도 많아 0%가 목표일 수 없다. |
| **B13** | 성부별 손가락 선호 실현도 | 설계 명세서 `RoleAffinity`의 보상 대상 손가락 비율(**실현율**)과 패널티 대상 손가락 비율(**기피 위반율**)을 `(role, hand)`별로 집계. 선호 집합 — MELODY/오른손: {4,5}(기피 {1}), MELODY/왼손: {1,2}(기피 {5}), BASS/오른손: {1}, BASS/왼손: {5}, INNER: {2,3}. | 높을수록 비용 함수 의도대로 작동 | **엔진의 성부 태깅 자체에 한계가 있다.** 엔진은 화음의 최고음(오른손)/최저음(왼손)을 MELODY/BASS로 찍으므로, **왼손 단음은 전부 BASS**가 된다. 단음 비율이 높은 곡에서 BASS/왼손 실현율(5번 선호)이 낮게 나오는 것은 운지 결함이 아니라 **태깅 방식의 산물**이다. 이 값은 "비용 함수가 태깅 결과에 얼마나 따랐는가"로만 읽어야 한다. |

## 4. 측정 불가 지표: 실연 운지 일치율

### 4.1 왜 측정할 수 없는가

"실제 피아니스트와 N% 일치"를 계산하려면 **동일한 MIDI 입력에 대해 사람이 배정한 손가락
번호(정답 라벨)** 가 음표마다 필요하다. 현재 저장소에는 그런 데이터가 **전혀 없다.**
엔진 출력만으로는 비교 대상이 존재하지 않으므로, 어떤 수치를 제시하더라도 그것은
측정값이 아니라 추정·창작에 해당한다.

따라서 **본 도구는 일치율을 출력하지 않으며, 보고서에도 측정값으로 기재할 수 없다.**

### 4.2 측정하려면 무엇이 필요한가

| 항목 | 요구 사항 |
|------|----------|
| **기준 데이터셋** | 대상 MIDI의 모든 음표에 `(pitch, start_ms, hand, finger)` 정답 라벨. 출판 악보의 편집자 운지(editorial fingering)를 전사하거나, 전공자가 직접 라벨링. |
| **라벨 규모** | 곡 일부(예: 32마디) 단위라도 가능하나, 구간별 편향을 피하려면 **서로 다른 2곡 이상·각 300음표 이상** 권장. |
| **라벨러 수** | 운지는 **정답이 유일하지 않다.** 최소 2명 이상이 독립 라벨링하고 **라벨러 간 일치도(IAA)** 를 먼저 보고해야 한다. IAA가 곧 엔진 성능의 상한이다. |
| **정렬 규칙** | 엔진 출력 음표와 정답 음표를 매칭하는 규칙(pitch 일치 + `start_ms` 허용 오차 ±30ms). 엔진이 drop한 음표·손 재배정된 음표의 처리 방침 명시. |
| **지표 정의** | ① 손가락 정확 일치율 ② 손(Left/Right) 일치율 ③ ±1 손가락 허용 일치율 ④ 손 일치 음표에 한정한 손가락 일치율. 단일 숫자로 뭉치지 말고 분해해 보고. |
| **라이선스** | 출판 악보 운지를 전사할 경우 저작권 확인 필요. |

### 4.3 공개 데이터셋 활용 시 주의

운지 라벨이 포함된 공개 데이터셋을 사용하는 방안도 있으나, **채택 전에 라이선스·라벨 체계
(손 번호 표기법, 교차·치환 표기)·MIDI 정렬 가능성을 직접 확인**해야 한다. 본 문서는 특정
데이터셋을 검증 없이 권하지 않는다.

### 4.4 보고서 기재 방식 (권고)

> - (가능) "하드 물리 제약 위반 N건 — 측정 도구 `tools/metrics.py`, 지표 정의 본 문서 §2"
> - (가능) "엔진 자체 규칙과의 자기일관성: 아르페지오 방향 불일치 X%"
> - **(불가)** "실제 피아니스트와 85% 일치" — 기준 데이터셋 구축 후에만 기재 가능

## 5. 지표 검출력 검산 (측정이 실제로 작동하는지)

"위반 0건"이라는 결과는 ① 정말 위반이 없음 ② 계산 코드가 돌지 않음 — 두 가지로 해석될 수
있다. 이를 구분하기 위해 `tests/test_metrics.py`는 **위반을 의도적으로 주입한 8음표 소형
샘플**을 만들어 각 지표의 검출 여부를 검증한다.

```
실행: cd 02_Implementation/01_Fingering
      python tests/test_metrics.py        (종료 코드 0 = 전원 검출 성공)
```

| 주입 케이스 | 주입 내용 | 기대 검출 |
|------------|----------|----------|
| 기준(정상) | 위반 없는 샘플 | 전 지표 0건 (오검출 없음) |
| A1 | 화음 f3–f5 간격을 13반음으로 확대 (한계 10) | A1 = 1 |
| A1b | 인접 쌍은 모두 통과하는 `[p56:f2, p62:f3, p71:f5]` | A1 = 0, A1b = 1 |
| A2 | 오른손 화음 손가락 순서 역전 | A2 = 2쌍 |
| A3 | f1 음의 `key_hold_ms`를 2000ms로 늘리고 후속 2음도 f1 배정 | A3 = 2쌍 |
| A3b | 중첩을 정확히 0.01ms로 설정 | A3 = 0, A3b = 1 (가짜 충돌 미계수 확인) |

| B10 | 오른손 상행인데 손가락 번호 감소 | B10 = 1 |
