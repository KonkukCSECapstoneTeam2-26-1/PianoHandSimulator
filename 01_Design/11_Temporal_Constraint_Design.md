## 1. 문제 정의

### 1.1 증상

운지법 엔진이 물리적으로 불가능한 자세를 출력한다.

```
Queen - Bohemian Rhapsody, t = 209463ms, 왼손
  (pitch 29, f5) (pitch 35, f3) (pitch 41, f2) (pitch 65, f4) (pitch 77, f1)
  → 한 손이 동시에 48반음(4옥타브)을 짚고 있음
```

### 1.2 규모

MIDI 13곡 결과를 **순간 단위**(한 손이 동시에 누르고 있는 건반 집합)로 검사한 결과:

| 항목 | 수치 |
|------|------|
| 2개 이상 동시 타건이 발생하는 시점 | 8,778 |
| 그중 MAX_SPAN 위반 | **2,930 (33.4%)** |
| 손가락 중복 (한 손가락이 두 건반) | **205** |
| Monotonicity 위반 (pitch 순 ≠ 손가락 순) | **2,074** |

곡별로는 13곡 중 9곡에서 발생하며, 비교적 단순한 `deb_clai`(드뷔시 '달빛')에서도
span 위반 132건, 손가락 중복 25건이 나온다.

### 1.3 기존 지표가 이를 놓친 이유

`tools/metrics.py` 의 A1·A2·A4 는 **화음 단위**로 검사한다. 화음은 온셋이 가까운
음표들의 묶음일 뿐 시간을 분할하지 않으므로, 화음 단위 검사는 실제 위반을 과소 보고한다.
동일 데이터에 대해 화음 단위로는 위반 3건, 순간 단위로는 5,209건이 나온다.

## 2. 원인 분석

### 2.1 제약을 거는 단위가 틀렸다

현재 엔진은 모든 물리 제약(MAX_SPAN, 손가락 유일성, Monotonicity)을
**화음(chord) 내부**에만 적용한다. 그러나 이 제약들이 성립해야 하는 단위는
**시간상의 한 순간**이다.

화음이 시간을 분할하지 못하는 이유는 두 가지다.

**(a) 지속음이 후속 화음과 겹친다**
음표는 `[start_ms, start_ms + key_hold_ms)` 동안 건반을 점유한다. 이 구간은
다음 화음, 그다음 화음까지 이어질 수 있다. DP는 화음 간 전이에서 직전 화음만
참조하므로 그 이전의 점유를 기억하지 못한다.

**(b) 같은 순간이 서로 다른 화음에 걸친다**
화음 그룹화는 "그룹의 첫 음표로부터 30ms 이내"라는 고정 윈도우를 쓴다.
따라서 온셋이 동일한 음표가 서로 다른 화음으로 갈라질 수 있다.

```
Right 178998.22  p81   ← 화음 A 시작
Right 179022.26  p46   ← A의 첫 음표로부터 24ms → A에 포함
Right 179022.26  p86   ← A에 포함
Right 179030.27  p43   ← 32ms → 화음 B 시작
```
분리·병합 과정을 거치면 `p46` 과 `p86` 이 서로 다른 화음에 속하면서도
**동일한 시각 179022.26 에 동시 타건**되는 상태가 만들어진다.

### 2.2 지속 범위 실측

각 음표의 점유 구간이 **몇 개의 후속 온셋까지 걸치는지** 측정했다 (13곡 전체, 20,436 음표).

| 걸치는 후속 온셋 수 | 비율 | 누적 |
|---:|---:|---:|
| 0 (겹침 없음) | 72.5% | 72.5% |
| 1 | 18.0% | 90.5% |
| 2 | 5.9% | 96.4% |
| 3 | 2.1% | 98.5% |
| 4 | 0.7% | **99.2%** |
| 5 이상 | 0.8% | 100% (최대 32) |

**→ 깊이 4까지만 기억하면 99.2%를 정확히 처리할 수 있다.** 이 수치가 아래 설계
대안의 실현 가능성을 결정한다.

## 3. 올바른 제약 모델

### 3.1 정의

한 손 `h` 에 대해, 시각 `t` 에서 점유 중인 음표 집합을

```
H_h(t) = { n : n.hand = h,  n.start ≤ t < n.start + n.key_hold }
```

로 정의한다. 물리 제약은 **모든 `t` 에 대해** 다음을 만족해야 한다.

| # | 제약 | 내용 |
|---|------|------|
| C1 | 손가락 유일성 | `H_h(t)` 의 음표들은 서로 다른 손가락을 가진다 |
| C2 | 손 범위 | `H_h(t)` 의 모든 손가락 쌍 `(fᵢ, fⱼ)` 에 대해 `\|pitchᵢ − pitchⱼ\| ≤ MAX_SPAN[fᵢ,fⱼ]` |
| C3 | 순서 | `H_h(t)` 를 pitch 오름차순 정렬했을 때 손가락 번호가 단조 (오른손 증가 / 왼손 감소) |

### 3.2 검사점의 유한성

`H_h(t)` 는 음표의 온셋과 해제 시점에서만 변한다. 따라서 모든 온셋·해제 시점
(음표 수의 2배)만 검사하면 전 구간을 덮는다. 연속 시간을 샘플링할 필요가 없다.

### 3.3 페달과 '필수 점유'

`key_hold_ms` 는 현재 **운지 확정 이후**에 "같은 손가락이 다시 필요한 시점"으로
산출된다. 즉 운지에 의존하므로, DP 도중에는 알 수 없다 (순환 의존).

이를 끊기 위해 **필수 점유 구간(required hold)** 을 운지와 무관하게 먼저 정의한다.

```
페달이 눌려 있지 않은 구간에서는 소리를 유지하려면 건반을 누르고 있어야 한다.
페달이 눌려 있으면 건반을 떼도 소리가 유지되므로 점유 의무가 없다.

required_hold(n) = n.start 부터, 페달이 꺼져 있는 동안 소리를 유지해야 하는 마지막 시점까지
                 (페달이 계속 눌려 있으면 최소 타건 시간만)
```

이 값은 MIDI와 CC64만으로 결정되므로 **DP 이전에 계산 가능**하며 경로에 의존하지 않는다.
따라서 "시각 `t` 에 어떤 음표들이 반드시 함께 눌려 있어야 하는가"가 DP 시작 전에 확정된다.

## 4. 설계 대안

### 대안 A — DP 상태에 점유 정보 포함

**상태**: `(현재 화음의 손가락 튜플, 아직 점유 중인 {손가락 → pitch} 매핑)`

전이 시 점유 매핑을 갱신한다. 현재 화음에서 다음 화음 시작 시점까지 살아남는
음표만 매핑에 남기고, 만료된 항목은 제거한다. 전이 비용 계산 시 C1~C3 를
`현재 화음 ∪ 점유 매핑` 전체에 대해 검사한다.

- **장점**: 전역 최적. 제약이 DP 내부에서 강제되므로 사후 수정이 불필요
- **단점**: 상태 공간 증가
- **실현 가능성**: 3.2절 실측상 72.5%의 음표는 점유 매핑이 비어 있고, 96.4%가
  2 이하다. 매핑을 희소 자료구조(frozenset)로 두면 실제 상태 수는 관리 가능한 수준.
  깊이 상한을 두고(예: 4) 초과분은 대안 C로 넘긴다

### 대안 B — 구간 그래프 색칠

점유 구간이 겹치는 음표끼리 간선을 긋고 5색(손가락)으로 칠한다.

- **장점**: C1(손가락 유일성)을 구조적으로 보장. 구간 그래프의 색칠은 다항시간
- **단점**: C2(span)·C3(순서)는 색 사이의 **거리 제약**이라 일반 색칠로 표현되지
  않는다. 음악적 비용 함수(레가토, 성부 선호)를 넣을 자리도 없다
- **판단**: C1 전용 보조 수단으로는 쓸 수 있으나 단독 해법은 아님

### 대안 C — DP 후 사후 수정

현행 DP를 유지하고, 위반 순간을 검출해 국소적으로 고친다.
(손가락 재배정 → 실패 시 점유 단축 → 실패 시 반대 손 이관 → 최후에 drop)

- **장점**: 구현 비용이 가장 낮고 기존 코드를 건드리지 않는다
- **단점**: 전역 최적이 아니며, 국소 수정이 인접 구간에 새 위반을 만들 수 있다.
  수렴 보장이 필요
- **판단**: 단독으로는 부족하나 A의 잔여 처리로 유효

### 대안 D — 화음 정의 자체를 재정의

화음을 "온셋 근접 묶음"이 아니라 "점유 구간이 겹치는 극대 클리크"로 바꾼다.

- **장점**: 가장 근본적
- **단점**: 클리크가 서로 겹쳐 선형 사슬을 이루지 않으므로 **DP의 전제가 깨진다**.
  엔진 전면 재작성에 가깝다
- **판단**: 이번 범위에서는 제외

## 5. 권고안

다음 4단계로 진행한다. 각 단계가 독립적으로 가치를 내며, 중간에 멈춰도 손해가 없다.

### 0단계 — 화음 그룹화의 시간 정합성 확보 (선행, 소규모) — **완료 (2026-10-05)**

동일 `start_ms` 음표가 서로 다른 화음에 배정되는 일이 없도록 보장한다.
그룹화 기준을 "그룹 첫 음표로부터 30ms" 에서 "직전 음표로부터 30ms 이내면 같은 그룹,
단 동일 온셋은 무조건 같은 그룹" 으로 바꾼다.
2.1(b) 유형의 위반이 제거되며, 작업량이 작고 즉시 측정 가능하다.

### 1단계 — 지표를 순간 단위로 확장 (선행, 필수) — **완료 (2026-10-05)**

A7(손 범위) · A8(손가락 중복) · A8b(건반 중복) · A9(순서) 추가.
현재 기준선 (13곡, 동시 타건 8,608시점): A7 2,752 / A8 0 / A8b 0 / A9 1,646.
A8·A8b 는 0단계의 건반 단위 점유 보정으로 해소되었다.

`tools/metrics.py` 에 순간 단위 지표를 추가한다 (A7 순간 span, A8 순간 손가락 중복,
A9 순간 순서). **고치기 전에 진실을 드러내는 것이 목적이다.** 현행 A1·A2·A4 는
화음 단위임을 문서에 명시하고 병기한다.

### 2단계 — 필수 점유 구간 산출 (대안 A의 전제) — **완료 (2026-10-06)**

3.3절의 `required_hold` 를 DP 이전에 계산하는 `compute_required_hold()` 를 추가했다.
페달 구간은 `parse_pedal_spans()` 결과를 재사용한다.
검증: `tests/test_required_hold.py` — 합성 케이스 9건 + 실데이터 25,249음표 불변식 (FAIL 0).

#### 실측 결과 — 효과는 페달 데이터가 있는 곡에 한정된다

| 곡 | 페달 구간 | 평균 duration | 평균 required_hold | 단축률 |
|---|---:|---:|---:|---:|
| `deb_clai` (드뷔시 '달빛') | 163 | 742.6 ms | 307.3 ms | **58.6%** |
| 나머지 12곡 | **0** | — | duration 과 동일 | 0.0% |

테스트 코퍼스 13곡 중 CC64 가 들어 있는 것은 `deb_clai` 하나뿐이다. 나머지는 게임 음악
MIDI 로 페달 정보가 없어 `required_hold == duration` 이 된다. 따라서 **DP 상태 부담은
코퍼스 전체로 보면 거의 줄지 않았다** (깊이 0 비율 73.1% → 73.8%).

다만 본 프로젝트의 목표는 피아노 연주 재현이고 실제 피아노 악보 MIDI 에는 페달 정보가
일반적으로 포함되므로, 이 메커니즘의 가치는 코퍼스 구성의 한계로 과소평가되고 있다.
**페달 정보가 있는 피아노 MIDI 를 테스트 코퍼스에 추가할 필요가 있다.**

#### 측정된 잠재 효과 (드뷔시 '달빛')

`key_hold_ms` 를 `required_hold` 로 추가 제한했을 때의 순간 단위 위반:

| 기준 | 동시 타건 시점 | A7 손 범위 | A9 순서 |
|------|---:|---:|---:|
| 현행 `key_hold = min(duration, 충돌)` | 629 | 114 | 49 |
| `required_hold` 로 추가 제한 | 454 | **57** | **15** |

총 점유 시간은 1020.2초 → 429.8초 (57.9% 단축). 페달이 눌려 있으면 손가락을 떼도
소리가 유지되므로 이는 물리적으로 타당한 단축이다.

> **다만 이 제한을 그대로 적용하지는 않았다.** `required_hold` 는 "최소 의무"이고
> 실제 연주자의 손가락 점유는 그보다 길다 (레가토 프레이징). 무조건 최소로 떼면
> 손가락이 불필요하게 자주 들려 모션이 부자연스러워진다.
> **제약을 위반하는 경우에만 `required_hold` 방향으로 단축**하는 것이 옳으며,
> 이는 위반 검출이 전제되므로 4단계에서 다룬다.

### 3단계 — DP 상태 확장 (대안 A) — **완료 (2026-10-06), 다만 효과는 제한적**

DP 상태를 `(현재 화음의 손가락 튜플, 점유 집합)` 으로 확장했다. 점유 집합의 항목은
`(화음 인덱스, 화음 내 위치, 손가락)` 이며, 전이에서 `required_hold` 기준으로 만료를
제거하고 직전 화음의 점유를 더해 갱신한다. 전이 비용에 C1~C3 위반 패널티를 더한다.
점유 깊이 상한 4, 빔 폭 120.

#### 결과

| | A7 (손 범위) | A9 (순서) |
|---|---:|---:|
| 1단계 기준선 | 2,752 | 1,646 |
| 3단계 적용 후 | 2,262 | 1,477 |
| 감소 | **−17.8%** | **−10.3%** |

실행 시간은 13곡 합계 13.9초 (최대 Bohemian Rhapsody 6.5초)로 목표(곡당 5초) 내.

#### 왜 목표(위반 1% 미만)에 크게 못 미쳤는가 — 원인 규명

탐색 용량과 가중치를 모두 의심해 실측했으나 **둘 다 원인이 아니었다.**

| 실험 | 결과 |
|------|------|
| 빔 폭 120 → 400 → 1200 | A7 104 / 104 / 104 — 변화 없음 |
| 점유 깊이 4 → 8 → 16 | A7 104 / 102 / 102 — 거의 변화 없음 |
| 점유 패널티 ×1 → ×10 → ×100 | A7 104 / 102 / 102 — 거의 변화 없음 |

DP 는 이미 자신이 선택할 수 있는 범위에서 최선을 내고 있었다. 그래서 **위반이 일어나는
순간의 음표 집합 자체가 연주 가능한지** 를 직접 검사했다 (어떤 손가락 조합으로도
MAX_SPAN 을 만족할 수 없는지).

| 곡 | 위반 시점 | 집합 자체가 연주 불가 | 비율 |
|---|---:|---:|---:|
| cac_am3_gm | 59 | 59 | 100.0% |
| anicro_am1 | 112 | 110 | 98.2% |
| Super Mario 64 - Medley | 399 | 383 | 96.0% |
| nds-mkds-titlescreen | 120 | 112 | 93.3% |
| wii-wiisports-titlescreen | 500 | 446 | 89.2% |
| Driftveil_City_BW | 122 | 98 | 80.3% |
| Queen - Bohemian Rhapsody | 1,019 | 752 | 73.8% |
| cac_kbo_bar | 124 | 83 | 66.9% |
| deb_clai | 97 | 40 | 41.2% |
| **합계** | **2,552** | **2,083** | **81.6%** |

**위반 시점의 81.6% 는 운지를 어떻게 배정해도 해가 없다.** 한 손에 동시에 놓인 음표들의
음역 자체가 손 범위를 넘기 때문이며, 이는 운지 결정(DP)이 아니라 **손 배정과 음표 유지**의
문제다. 현재 `split_wide_chords_between_hands()` 는 **화음 단위 span** 만 검사하고,
"이미 눌려 있는 음"과 "멀리서 새로 치는 음"의 충돌은 전혀 보지 않는다.

즉 3단계로 고칠 수 있는 몫은 나머지 18.4% 였고, 실제로 그 범위에서 개선이 일어났다.

### 4단계 — 순간 단위 손 배정 (대안 C에서 **범위 확대**) — **완료 (2026-10-06)**

3단계 실측에 따라 4단계의 성격이 바뀐다. 당초 "DP 가 못 잡은 잔여를 국소 수정" 하는
보조 단계로 두었으나, **위반의 81.6% 가 손 배정 단계에서 결정되는 문제**임이 드러났으므로
4단계가 본 과제의 주된 해결 단계가 된다.

핵심: `split_wide_chords_between_hands()` 의 판정을 **화음 단위에서 순간 단위로** 올린다.
현재는 "이 화음의 음표들을 한 손으로 짚을 수 있는가"만 보지만,
"이 순간에 **눌려 있는 음표 전체**를 한 손으로 짚을 수 있는가"를 보아야 한다.

처리 순서 (비용이 낮은 것부터):
1. **점유 단축** — `key_hold` 를 줄여 충돌을 피한다. 하한은 `required_hold`
   (그 아래로는 소리가 끊긴다). 페달이 눌린 구간에서는 크게 줄일 수 있다.
   달빛 실측: 이 방법만으로 A7 114 → 57, A9 49 → 15
2. **반대 손 이관** — 순간 단위로 재검사하여 이관 가능하면 옮긴다
3. **손가락 재배정** — 국소 DP 재실행
4. **drop** — 위 셋으로 해결되지 않으면 음표를 버리되, **무엇을 왜 버렸는지 반드시 보고**

#### 구현 결과

`resolve_instant_conflicts()` 를 추가해 1)과 4)를 구현했다. 온셋을 시간순으로 한 번
훑으며, 위반이 있는 순간에 '지금 눌리는 음에서 음역이 가장 먼 유지음'을 떼는 방식이다.
점유 단축은 이후 시점의 점유 집합을 줄이기만 하므로 새 위반을 만들지 않아 단일 전진
패스로 충분하다.

단축 가능 조건에 **최소 타건 시간**을 걸었다. 타건 후 `MIN_STRIKE_HOLD_MS`(30ms)도
지나지 않은 음을 떼는 것은 물리적으로 불가능하므로(누르고 떼는 동작 자체에 시간이 든다),
그런 음은 사실상 동시 타건으로 보고 drop 경로로 보낸다. 이 조건을 넣기 전에는 8ms 만에
건반을 눌렀다 떼는 결과가 나왔다.

| 항목 | 수치 |
|------|------|
| 점유 단축 | 2,353건 |
| └ 소리 희생을 동반 (페달 없는 구간) | 2,296건 |
| 음표 제외 (drop) | 37개 |
| **미해결 시점** | **0** |

#### 최종 검증 — 전 결과 파일 하드 제약 위반 0건

실곡 13곡 + 기준 코퍼스 7곡, 총 20개 결과 파일 모두 A1~A9 위반 0건 (ALL PASS).
회귀 테스트 5종(`test_midi_timing` / `test_keyboard_geometry` / `test_metrics` /
`test_required_hold` / `test_reference_corpus`) 전부 통과.

#### 음표 보존 현황 — 남은 과제는 '분리 단계의 drop'

| 구분 | 수량 | 비고 |
|------|---:|------|
| 파싱 음표 | 25,249 | |
| 중복 보이싱 병합 | 2,275 | **손실 아님** — 한 건반을 두 트랙이 동시에 치는 것을 하나로 합침 |
| 연주 불가로 분리 단계에서 drop | 2,525 | 양손 어디에도 배정 불가 |
| 4단계 drop | 37 | |
| 최종 출력 | 20,412 | 보존율 80.8%, **실제 손실 10.1%** |

곡별 보존율은 입력 성격을 그대로 반영한다.

| 곡 | 보존율 |
|---|---:|
| `deb_clai` (드뷔시 '달빛', 피아노 악보) | **100.0%** |
| `Super Mario 64 - Medley` | 99.5% |
| `nds-mkds-titlescreen` | 84.5% |
| `Queen - Bohemian Rhapsody` (밴드 편곡) | 67.2% |

**피아노 악보 기반 입력은 음표를 하나도 잃지 않고 물리 제약도 전부 만족한다.**
손실은 두 손으로 연주할 수 없는 편곡에 집중되어 있다.

분리 단계의 drop(2,525개)은 이전까지 **아무 보고 없이** 일어났다. 이번에 집계·경고를
추가해 드러냈으나, 처리 방식 자체는 여전히 '잘라내기'다. 성부 중요도 기반 선택이나
아르페지오 분산(온셋 미세 분할)으로 개선하는 것은 별도 설계가 필요하다
(`02_Fingering_Design_Spec.md` 8장 이슈 6번).

#### 전제: 테스트 코퍼스의 한계 — **기준 코퍼스 도입으로 해소 (2026-10-06)**

위 표에서 보듯 연주 불가 비율은 곡 성격에 크게 의존한다 (달빛 41.2% vs 게임 음악 90%+).
게임 음악 MIDI 는 피아노 연주를 전제로 편곡된 것이 아니어서 애초에 두 손으로 연주할 수
없는 구간이 많다. 이 코퍼스로 측정한 위반율은 엔진의 성능이 아니라 입력의 성격을 더 많이
반영하므로, **개선 효과를 측정할 기준이 되지 못한다.**

이를 해소하기 위해 **연주 가능함이 보장된 기준 코퍼스**를 도입했다.

- 생성기: `02_Implementation/01_Fingering/tools/make_reference_corpus.py`
- 출력: `assets/midi/reference/ref_01 ~ ref_07` (7곡, 354음표)
- 검증: `tests/test_reference_corpus.py`

각 순간에 한 손이 점유하는 음표 집합이 반드시 유효한 손가락 배정을 갖도록 구성했고,
그 사실을 **엔진을 거치지 않고 독립 검증**한다. 따라서 이 코퍼스에서 나온 위반은
전부 엔진 결함이며 목표값은 명확히 0이다.

외부 MIDI 를 수집하지 않고 생성한 이유는 두 가지다. ① 요구사항 3.8(저작권) 상 출처가
불분명한 음원을 저장소에 포함하기 어렵다. ② 수집한 곡은 연주 가능 여부를 알 수 없어
지금과 같은 '엔진 결함인가 입력 문제인가' 혼동이 되풀이된다.

| 곡 | 겨냥한 상황 |
|---|---|
| `ref_01_five_finger` | 고정 5지 포지션 단선율 (기본 동작) |
| `ref_02_block_chords` | 3화음 블록 |
| `ref_03_alberti` | 알베르티 베이스 + 선율 |
| `ref_04_pedal_arpeggio` | 페달로 유지되는 아르페지오 — `required_hold` 메커니즘 |
| `ref_05_sustained_bass` | 페달 하 지속 베이스 |
| `ref_06_position_shift` | 쉼표로 분리된 포지션 이동 |
| `ref_07_inner_voice` | **페달 없이 손가락으로 유지되는 내성** — 3단계 점유 상태 확장 |

#### 측정 결과 — 기준 코퍼스에서 엔진 위반 0건

| 곡 | 동시 타건 시점 | 손 범위 | 손가락 중복 | 순서 |
|---|---:|---:|---:|---:|
| `ref_02_block_chords` | 12 | 0 | 0 | 0 |
| `ref_04_pedal_arpeggio` | 24 | 0 | 0 | 0 |
| `ref_05_sustained_bass` | 4 | 0 | 0 | 0 |
| `ref_07_inner_voice` | 40 | 0 | 0 | 0 |
| 나머지 3곡 (순차 타건) | 0 | 0 | 0 | 0 |
| **합계** | **80** | **0** | **0** | **0** |

**엔진은 다룰 수 있는 입력에서 물리 제약을 모두 지킨다.** 특히 `ref_07_inner_voice` 는
페달 없이 점유가 후속 화음까지 실제로 걸치는 곡으로, 3단계 DP 상태 확장이 겨냥한 상황을
직접 검증한다.

따라서 게임 음악 코퍼스의 위반 2,262건(A7)·1,477건(A9)은 엔진의 정확도 지표로 읽어서는
안 되며, **입력의 연주 가능성 지표로 읽어야 한다.** 4단계의 성과도 기준 코퍼스가 아니라
실곡 코퍼스에서 "연주 불가 입력을 얼마나 합리적으로 처리했는가"로 평가해야 한다.

## 6. 검증 전략

| 단계 | 검증 방법 | 목표 |
|------|----------|------|
| 0 | 동일 온셋이 서로 다른 화음에 속하는 건수 | 0 |
| 1 | 순간 단위 지표가 기존 수치(span 2,930 / 중복 205 / 순서 2,074)를 재현 | 일치 |
| 2 | `required_hold ≤ duration_ms` 및 페달 구간과의 정합성 | 전건 성립 |
| 3 | 순간 단위 위반 수 감소 추이, DP 실행 시간 | 위반 1% 미만, 곡당 5초 이내 |
| 4 | 순간 단위 위반 | 0 (drop 건수는 별도 보고) |

기존 회귀 테스트(`test_midi_timing`, `test_keyboard_geometry`, `test_metrics`)가
계속 통과해야 한다. 3단계에서 운지 결과가 대폭 바뀌므로 `metrics.py` 의 품질 지표(B군)를
변경 전후로 비교해 음악적 품질이 퇴화하지 않았는지 함께 본다.

## 7. 리스크 및 미결 사항

| # | 항목 | 내용 |
|---|------|------|
| 1 | 상태 공간 폭발 | 3단계에서 DP 실행 시간이 급증할 수 있다. 깊이 상한과 상태 가지치기(동일 점유 매핑 중 비용 최소만 유지)로 대응하되, 실측 후 상한을 조정한다 |
| 2 | 해가 없는 구간 | 편곡 자체가 두 손으로 연주 불가능한 경우가 있다 (밴드 편곡 MIDI). 이때는 음표를 버릴 수밖에 없으며, **무엇을 왜 버렸는지 반드시 보고**해야 한다 |
| 3 | `required_hold` 의 근사 | 페달 유무만으로 점유 의무를 판정하는 것은 단순화다. 하프 페달, 페달 없이 레가토로 잇는 주법 등은 반영되지 않는다 |
| 4 | 음표 drop 정책 | 현행은 '잘라내기'다. 성부 중요도 기반 선택이나 아르페지오 분산(온셋 미세 분할)이 음악적으로 더 낫지만 별도 설계가 필요하다 |
| 5 | IK 영향 | 3단계 이후 운지가 대폭 바뀐다. IK 파트가 이미 연동을 시작했다면 재생성 시점을 협의해야 한다 |
