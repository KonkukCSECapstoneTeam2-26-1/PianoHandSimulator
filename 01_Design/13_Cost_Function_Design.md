# 운지법 코스트 함수 — 제약과 선호도의 분리

**작성**: 정근녕 · 2026-11-01
**계기**: 10/30 2차 중간발표 지도교수 지적
**관련**: `11_Temporal_Constraint_Design.md` (순간 단위 제약 재정의), `10_Fingering_Metrics_Definition.md`

---

## 1. 지적 내용

발표 중 두 차례, 마무리에서 한 차례 더 나왔다. 요지는 다음과 같다.

> 절대 위반해서는 안 되는 제약을 가산 코스트에 섞으면, 다른 항이 낮아질 때 전체 합이 작아져
> 위반이 선택될 수 있다. max를 쓰는 방법, 곱을 쓰는 방법 등 결합 방식이 여러 가지 있으니
> 비교해 볼 필요가 있다. 또는 제약을 먼저 걸러 낸 뒤 남은 후보에 대해서만 코스트로 고르는
> 방식도 있다. 그렇게 하면 터지는 경우를 많이 줄일 수 있을 것이다.

## 2. 현재 구조

`piano_fingering_engine.py` 의 화음 단위 동적 계획법은 **하나의 스칼라**를 최소화한다.

```python
cost = (prev_c
        + calc_transition_cost(prev_chord, prev_f, curr_chord, curr_f)
        + occupancy_penalty(curr_chord, curr_f, held_now))
```

후보 생성은 제약을 보지 않는다. `get_combinations(k)` 는 C(5,k) 조합을 그대로 반환한다.

```python
def get_combinations(k):
    if k > 5: k = 5
    combos = list(combinations(range(1, 6), k))
    if hand_id == 0:
        return [tuple(reversed(c)) for c in combos]
    return combos
```

제약 위반은 큰 수를 더하는 방식으로만 다룬다.

| 구분 | 항목 | 값 |
|---|---|---|
| 하드 제약 | `OCCUPANCY_FINGER_PENALTY` — 한 손가락이 두 건반 | 4000 |
| | `OCCUPANCY_SPAN_PENALTY` — 순간 손 범위 초과 | 5000 |
| | `OCCUPANCY_ORDER_PENALTY` — 음높이 ↔ 손가락 순서 역전 | 1500 |
| | 화음 내 span 초과 | +5000 |
| | 화음 간 순서 역전 (4개 분기) | +2000 |
| | 손 교차에 가까운 이동 | +2500 |
| 선호도 | `FINGER_DIFFICULTY` | 손가락별 상수 |
| | 성부 역할 보정 | −12 ~ +20 |
| | 순차 진행 보상 / 도약 패널티 | −20 / +30 |
| | 엄지 넘기기 보정 | −20 ~ +40 |
| | 손목 이동 | 초과분 × 2 |
| | 흑건 엄지 | +25 |

코드 전체에서 `penalty +=` 가 19곳이다. 하드 제약과 선호도가 **같은 스칼라에 더해진다.**

`is_chord_playable()` 의 주석에는 이 구조의 결과가 이미 적혀 있다.

> "그 경우 DP는 **+5000 패널티를 물고 물리적으로 불가능한 운지를 출력한다.**"

이 함수는 화음 분리 전처리에서만 쓰이고 DP 내부 후보 생성에는 쓰이지 않는다.

## 3. 왜 문제인가

### 3.1 위반이 선호도와 교환된다

DP는 경로 전체의 합을 최소화한다. 위반 패널티는 **발생 지점에서 한 번** 더해지지만,
선호도 항은 **화음마다 계속** 쌓인다. 따라서 위반이 있는 경로라도 이후 구간에서 선호도를
충분히 아끼면 전체 합이 더 작아질 수 있다.

화음당 선호도 차이가 30 정도만 나도 200화음이면 6000이다. `OCCUPANCY_SPAN_PENALTY` 5000보다 크다.
곡이 길수록 이 교환은 쉬워진다.

### 3.2 빔 가지치기에서 사라진다 — 더 심각한 쪽

상태 폭발을 막기 위해 화음마다 상위 `DP_BEAM_WIDTH = 120` 개만 남긴다.

```python
if len(curr_states) > DP_BEAM_WIDTH:
    kept = sorted(curr_states.items(), key=lambda kv: kv[1][0])[:DP_BEAM_WIDTH]
    curr_states = dict(kept)
```

정렬 기준이 **같은 스칼라**다. 위반 없는 상태가 선호도 때문에 순위가 밀리면 그 자리에서 잘려 나간다.
한 번 잘리면 이후 어떤 구간에서도 복구되지 않는다. 즉 3.1 은 "나쁜 쪽이 선택될 수 있다"지만
이쪽은 **"좋은 쪽이 아예 후보에서 사라진다"** 이다.

### 3.3 위반의 가격이 선형이다

두 곳에서 위반하면 +10000 이다. 그러나 물리적으로는 한 번만 위반해도 이미 불가능하다.
가산 구조는 불가능을 "양"으로 다루게 되어, 많이 위반하는 경로와 한 번 위반하는 경로를
연속적인 값으로 비교한다.

### 3.4 현재 위반 0건이 이 문제를 가리고 있다

지금 21곡에서 순간 단위 위반이 0건인 것은 사실이다. 다만 그것은 DP가 잘 골라서가 아니라,
**DP 뒤에 붙인 사후 해소**(`resolve_instant_conflicts`)와 **화음 분리**가 남은 위반을 치우기 때문이다.
따라서 현재 지표로는 코스트 구조의 품질을 볼 수 없다. 이 점이 아래 측정 설계의 출발점이다.

## 4. 선택지

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **A. 후보 배제** | 제약을 만족하는 후보만 생성 | 위반이 구조적으로 불가능. 탐색 공간도 줄어든다 | 모두 배제되면 해가 없다. 폴백이 필요 |
| **B. 사전식 비교** | 코스트를 `(위반 수, 선호도 합)` 튜플로 두고 사전식 비교 | 위반과 선호도가 절대 교환되지 않는다. 불가피하면 최소 위반을 고른다 | 상태 비교·정렬을 전부 튜플로 바꿔야 한다 |
| **C. max** | 경로의 최대 위반 심각도로 평가 | "가장 나쁜 한 곳"을 피한다 | 심각도 척도를 새로 정의해야 한다. 같은 등급 안에서 구분이 안 된다 |
| **D. 곱** | 실현 가능성을 곱한다 | 0을 곱하면 완전 배제 = A 와 동치 | 실수 곱은 스케일 해석이 어렵고 튜닝 변수가 는다 |

### 4.1 A 를 그대로 쓸 수 없는 이유

제약을 **언제 판정할 수 있는가**가 제약마다 다르다.

| 제약 | 판정 시점 | 배제 가능 지점 |
|---|---|---|
| 화음 내부 span | 화음과 손가락 조합만 보면 됨 | **후보 생성 시점** — `get_combinations` 에서 거를 수 있다 |
| 순간 단위 점유 (손가락 중복·범위·순서) | 이전 상태의 점유 집합이 필요 | **전이 시점** — 후보 생성에서는 알 수 없다 |

따라서 A 는 "후보 배제"만으로 끝나지 않고 **전이 금지**를 포함해야 한다.
`calc_transition_cost` 가 위반을 만나면 그 전이를 버리는(무한대) 구조가 된다.

### 4.2 권장안 — A + B

1. 화음 내부 span 위반 조합은 **후보 생성에서 제외**한다.
2. 순간 단위 위반이 생기는 전이는 **버린다.**
3. 모든 전이가 버려지는 화음에서는 B 로 떨어진다 — `(위반 수, 선호도 합)` 사전식으로
   최소 위반을 고른다. 현재의 화음 분리 로직은 그다음 단계로 둔다.
4. 빔 가지치기 정렬도 같은 튜플 기준으로 바꾼다. **3.2 를 막으려면 이 항목이 필수다.**

C 와 D 는 새로운 튜닝 변수(심각도 척도, 곱 스케일)를 만드는 데 비해 얻는 것이 A+B 와 같다.
다만 지도교수가 비교를 요구했으므로 아래 측정에 함께 넣는다.

## 5. 측정 설계

### 5.1 무엇을 재야 하는가

최종 위반 수는 이미 0이므로 비교에 쓸 수 없다(3.4). **사후 해소를 끄고 DP 직후를 재야** 한다.

| 지표 | 정의 | 왜 보는가 |
|---|---|---|
| **DP 직후 위반 수** | `resolve_instant_conflicts` 와 화음 분리를 끈 상태에서 센 순간 단위 위반 | 코스트 구조의 직접적 품질 |
| 음표 보존율 | 최종 출력 / 입력 음표 수 | 분리·드롭이 줄면 올라간다 |
| 최종 위반 수 | 현행 지표 | 0 이 유지되는지 확인 |
| 처리 시간 | 21곡 일괄 | 후보 배제로 빨라지는지, 튜플 비교로 느려지는지 |
| 빔 포화율 | 화음당 상태 수가 120 에 닿는 비율 | 3.2 가 실제로 일어나는 구간을 찾는다 |

### 5.2 비교 대상

| 조건 | 내용 |
|---|---|
| 기준 | 현행 가산 |
| A+B | 권장안 |
| C | max 기반 |
| D | 곱 기반 |

입력은 기준 코퍼스 8곡(ref_01~08)과 실곡 13곡을 나눠 본다.
기준 코퍼스는 연주 가능함이 보장되므로 **DP 직후 위반이 0 이어야 정상**이다.
여기서 위반이 남으면 그것은 입력 탓이 아니라 코스트 구조 탓이다.

### 5.3 먼저 확인할 것

권장안을 구현하기 전에, **3.1 과 3.2 가 실제로 일어나는지** 현행 코드에서 먼저 센다.

1. DP 직후 위반 수 (사후 해소를 끄고)
2. 잘려 나간 상태 중 위반이 없는 것의 비율 — 빔 가지치기 직전/직후를 비교
3. 위반을 포함한 채 선택된 경로가 있다면, 그 경로가 이긴 선호도 차이의 크기

이 수치가 없으면 "고쳐서 좋아졌다"를 말할 수 없다. 추측으로 고치지 않는다.

## 5.4 측정 결과 (2026-11-01)

5.3 을 실제로 쟀다. 저장소 코드는 수정하지 않고, 엔진 소스를 읽어 가지치기 지점에만
카운터를 끼운 사본을 메모리에서 실행했다.

| | 기준 코퍼스 8곡 | 실곡 13곡 |
|---|---|---|
| 음표 수 | 412 | 21,556 |
| **DP 직후 위반 시점** | **0** | **2,384** |
| 사후 해소 후 위반 시점 | 0 | 0 |
| 빔 포화가 일어난 화음 | 16 / 362 (4.4%) | 885 / 12,377 (7.2%) |
| 가지치기로 버린 상태 | 5,300 | 202,780 |
| 그중 위반이 없던 상태 | 455 (8.6%) | 2,922 (1.4%) |
| 남긴 상태 중 위반이 있던 것 | 1,247 | 95,946 |

### 해석

**3.1 (위반이 선호도와 교환된다) — 현재 관측되지 않음.**
연주 가능함이 보장된 기준 코퍼스에서 DP 직후 위반이 0이다. 즉 입력이 실제로 칠 수 있는
곡이면, 현행 가산 구조도 위반을 고르지 않는다. 빔에는 위반 상태가 많이 남지만
(실곡 95,946개) 최종 역추적에서는 선택되지 않는다. 4000~5000 의 패널티가 적어도
지금 입력 범위에서는 제 역할을 하고 있다.

**3.2 (좋은 상태가 가지치기에서 사라진다) — 관측됨.**
`ref_04_pedal_arpeggio` 는 화음의 53.3% 에서 빔이 포화되며, 그 과정에서 **위반 없는 상태
455개를 버리면서 위반 있는 상태 1,247개를 남겼다.** 연주 가능함이 보장된 입력에서도 일어난다.
다만 이 곡의 최종 DP 직후 위반은 0 이므로, **결과를 바꾸지는 않았다.**
버려진 무위반 상태들은 비용이 높아 어차피 최적 경로가 아니었던 것으로 보인다.

**실곡의 2,384 위반은 입력 탓이다.** 기준 코퍼스 0건이 그 증거다.
이는 기존에 측정한 "위반 시점의 81.6% 가 애초에 연주 불가능한 구간"과 일치한다.

### 결론 — 권장안 수정

지도교수 지적은 **구조적으로 타당하지만, 현재 품질 문제의 원인은 아니다.**
따라서 4.2 의 전면 재설계를 그대로 밀어붙일 근거가 없다. 다음과 같이 조정한다.

| 항목 | 조정 |
|---|---|
| 후보 배제 · 전이 배제 · 사전식 비교 | **보류.** 효과를 입증할 측정 근거가 없다. 3.1 이 재현되는 입력을 먼저 찾는다 |
| **빔 정렬 기준을 `(위반 수, 선호도 합)` 으로 변경** | **진행.** 3.2 는 실제로 관측되며, 변경 범위가 정렬 키 한 줄로 작고 부작용이 적다 |
| 가산 / max / 곱 비교 | 3.1 재현 입력을 확보한 뒤로 미룬다 |

### 다음에 할 것

3.1 을 재현하려면 **연주는 가능하지만 선호도 비용이 큰 입력**이 필요하다.
기준 코퍼스는 짧고 쉬워서(평균 52화음, 8곡 중 5곡은 빔이 포화조차 되지 않음) 이 조건을 만들지 못한다.
아래 성격의 기준 입력을 추가해 재측정한다.

- 긴 곡 — 선호도 차이가 누적될 시간이 있어야 5000 을 넘길 수 있다
- 포지션 이동이 잦은 곡 — 손목 이동 패널티가 크게 쌓인다
- 흑건 엄지가 반복되는 곡 — `+25` 가 반복 누적된다
- 손이 넓게 벌어진 채 유지되는 곡 — 빔이 포화되도록

## 7. 주의

- **현재 위반 0건을 깨뜨리지 않아야 한다.** 구조를 바꾸는 과정에서 일시적으로 늘 수 있으나,
  최종 상태는 기존과 같거나 나아야 한다.
- 기준 코퍼스 8곡의 위반 0건은 **엔진 정확도의 기준선**이다. 여기서 늘면 즉시 되돌린다.
- 실곡의 위반 수는 입력의 연주 가능성을 나타내는 지표이지 엔진 정확도가 아니다(10번 문서).
  두 가지를 섞어서 비교하지 않는다.
