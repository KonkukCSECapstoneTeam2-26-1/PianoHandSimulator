- SkeletalMesh : 입력 데이터 및 원본 모델
- SkeletalMeshToCollection : 데이터 포맷 변환
    - Chaos Flesh는 geometry 데이터 구조를 사용하기 때문에 SKM을 바로 못 쓰고 Collection으로 변환해줘야 함.
    - ⇒ **즉 엔진이 이해할 수 있는 형태로 바꿔줌**
- CreateTetrahedron : 표면 메쉬를 사면체 구조로 바꿔줌
    - 내부를 채우고 사면체 구조로 쪼갬
    - why? ⇒ 물리 시뮬레이션을 적용할 수 있는 형태로 변환하기 위해서
    - 위쪽 노드 : Collection = 오로지 구조 및 형태만 필요 → 그렇기 때문에 전단계에서 transformOnly 체크
    - 아래쪽 노드 : 속성 공급용 및 원본 보관소 → 원본 그대로 사용
    - 양갈래로 나눈 이유 ⇒ 역할 분리를 하기 위해서 (위쪽은 물리용 구조 생성, 아래쪽은 데이터 보존 전용) ⇒ **속성 오염없이 정확하게 복사하고 관리하기 위함**
- TransferVertexAttribute : 데이터 복사
    - SourceCollection → 새로 만든 tetra mesh로
    - 특정 attribute를 복사
    - why?
        - CreateTetrahedron 하면:
            
            👉 “형태만 새로 만들어짐”
            
            👉 원래 있던 색/정보는 사라짐
            
    - ⇒ **“겉모습/속성 유지”**
- FleshAssetTerminal : 최종 출력
    - 지금까지 만든 걸 FleshAsset으로 저장
    - ⇒ **재사용 가능한 최종 결과**

- GetFleshAsset : 소프트바디 데이터 컨테이너를 불러오는 것
    - 말 그대로 “작업 대상”을 가져오는 지
- SetFleshDefaultProperties : Flesh 시뮬레이션 기본값 세팅
    - 탄성
    - damping
    - mass 등등
    - 즉 물성 초기화 단계
- **SetFleshBonePositionTargetBinding**
    - 뼈 위치를 Flesh에 바인딩
    - 특정 vertex들이 뼈를 따라가도록 설정
    - 즉 애니메이션(리깅)과 Flesh 부분을 연결
- SetVertexTrianglePositionTargetBinding
    - 삼각형 기준으로 타겟 바인딩
    - 렌더용 메시(surface mesh)와 Flesh 내부를 연결할 때 사용
    - Bone Binding과의 차이점
        - Bone : 리깅 기반
        - Triangle : 표면 유지/형상 보존
- VisualizeKinematicFaces : 디버그용
    - 어떤 부분이 Kinematic(고정)인지 시각화
    - 즉 물리 영향을 안 받고 따라가는 영역 확인
- VisualizePositionTargets : 디버그용
    - 바인딩된 타겟 위치를 표시
    - 제대로 붙었는지 확인
- FleshAssetTermianl
    - 최종 출력
    - 이 DataFlow 결과를 엔진이 실제 Asset에 적용
- DataFlow를  두개로 나누는 이유
    - 오늘 정리한 Dataflow
        - 시뮬레이션 제어/바인딩
    - 이전에 정리한 Dataflow
        - Geometry 생성/ 전처리
        - 시뮬레이션용 메쉬를 만드는 단계
    - 재사용성 확보 가능
        - 메쉬는 공유, 바인딩은 캐릭마다 다름
        - 성능 & 캐싱
            - 테트라 생성은 비용이 크기 때문에 매번 만들면 비효율 ⇒ 만들어놓고 재사용
