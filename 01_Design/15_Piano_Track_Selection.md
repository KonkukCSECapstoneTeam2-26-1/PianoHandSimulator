## 0. 왜 이 문서가 필요했는가

요구사항 2.3 에 「멀티트랙 MIDI(format 1)의 경우 피아노 트랙을 자동 선별한다」가
들어 있으나 **구현이 없었다.** 엔진은 모든 트랙의 음표를 한 덩어리로 합친 뒤
88키 음역(MIDI 21~108) 밖만 잘라내고 있었고, 소스 주석에도 그 사실이
`요구사항 2.3의 피아노 트랙 자동 선별은 미구현 상태` 로 적혀 있었다.

이것이 실제로 무엇을 만들어 내고 있었는지 먼저 측정했다.

### 0.1 측정 — 드럼이 건반으로 운지되고 있었다

| 곡 | 전체 음표 | 타악 채널 | 비중 |
|---|---:|---:|---:|
| anicro_am1 | 507 | 353 | **69.6%** |
| nds-mkds-titlescreen | 3,532 | 1,447 | 41.0% |
| cac_kbo_bar | 1,932 | 750 | 38.8% |
| nds-acww-0600 | 732 | 264 | 36.1% |
| cac_am3_gm | 476 | 135 | 28.4% |
| wii-wiisports-titlescreen | 3,823 | 773 | 20.2% |
| Queen - Bohemian Rhapsody | 5,925 | 1,114 | 18.8% |
| Driftveil_City_BW | 1,377 | 214 | 15.5% |
| Super Mario 64 - Medley | 5,435 | 0 | 0% |
| deb_clai | 1,491 | 0 | 0% |

실곡 10곡 중 **8곡**에 GM 타악 채널이 있었고, 그 음표가 전부 운지 대상이었다.

음역 필터가 이것을 걸러내지 못한 이유는 다음과 같다. General MIDI 규격에서
10번 채널(0-base 9)은 타악 전용이고, 이 채널의 note 번호는 **음높이가 아니라
악기 번호**다 (35 = Bass Drum, 38 = Snare 등). 그런데 그 번호의 실제 분포가
35~81 이어서 88키 음역(21~108) 안에 완전히 들어온다. 즉 **스네어 한 대가
건반 한 개로 해석되어 손가락이 배정되고 있었다.**

메모에 남아 있던 "잔여 음표 손실 약 15% 가 밴드 편곡 곡에 집중" 의 원인도
대부분 여기였다. 드럼은 짧은 음이 빽빽하게 동시 타격되므로, 다섯 손가락
한계와 순간 점유 제약을 먹어 치우고 **실제 선율 음표를 밀어냈다.**

### 0.2 요구사항 2.3 의 기준과 측정 결과의 충돌

요구사항 2.3 은 선별 기준을 우선순위 순으로 셋 제시한다.

| # | 요구사항의 기준 | 본 설계의 채택 여부 |
|---|---|---|
| 1 | GM 프로그램 0~7(Piano 계열)에 해당하는 트랙 | **조건부 채택** (§2) |
| 2 | 음역대가 A0~C8 에 집중된 트랙 | 미채택 — 기존 음역 필터가 이미 담당 |
| 3 | 노트 이벤트 수가 가장 많은 트랙 | **미채택** (§4.1) |

1번을 문자 그대로 적용하면 안 된다는 것이 측정에서 드러났다.
1단계 제외를 통과한 음표 중 피아노 음색(program 0~7)이 차지하는 비율은
다음과 같다.

| 곡 | 연주 가능 음표 | 피아노 음색 | 점유율 |
|---|---:|---:|---:|
| Super Mario 64 - Medley | 5,435 | 5,435 | 100.0% |
| deb_clai | 1,491 | 1,491 | 100.0% |
| nds-acww-0600 | 430 | 284 | 66.0% |
| cac_am3_gm | 321 | 182 | 56.7% |
| Queen - Bohemian Rhapsody | 4,811 | 1,920 | 39.9% |
| nds-mkds-titlescreen | 2,085 | 549 | 26.3% |
| wii-wiisports-titlescreen | 3,050 | 380 | 12.5% |
| Driftveil_City_BW | 1,163 | 78 | 6.7% |
| cac_kbo_bar | 1,182 | 54 | 4.6% |
| anicro_am1 | 154 | 0 | 0.0% |

`cac_kbo_bar` 는 피아노 음색이 4.6%(54개)뿐이다. 「피아노 음색 트랙만 쓴다」를
문자 그대로 적용하면 1,182개 중 54개만 남아 **곡이 사라진다.** `anicro_am1` 은
피아노 음색이 아예 없어 전곡이 비게 된다.

요구사항의 기준은 **입력이 피아노 편곡이라는 암묵적 전제** 위에 쓰여 있고,
실제 코퍼스의 다수는 그 전제를 만족하지 않는다. 그래서 전제가 성립하는지를
먼저 판정하는 단계를 넣었다.

## 1. 1단계 — 연주 불가 음원 제외 (무조건)

건반으로 연주할 수 없는 음원을 **조건 없이** 제외한다.

| 대상 | 근거 |
|---|---|
| GM 타악 채널 (channel 9, 0-base) | note 번호가 음높이가 아니라 악기 번호. 건반 좌표로 해석할 수 없다 |
| program 112~127 | 112~119 Percussive, 120~127 Sound Effects. 음고 의미가 없거나 건반 연주 대상이 아니다 |

이 단계는 **판단이 들어가지 않는다.** 규격상 음높이가 아닌 값을 음높이로
해석하던 것을 멈추는 것이므로, 임계값도 예외도 없다.

`program 111`(Shanai)과 `program 112`(Tinkle Bell)의 경계, `program 7`(Clavi)과
`program 8`(Celesta)의 경계는 테스트로 고정했다.

### 1.1 program 귀속 — 채널 단위·시간 순

`program_change` 는 **채널 단위 상태**이고 파일 전체에 걸쳐 시간 순으로 바뀐다.
처음에는 트랙별로 따로 추적했으나, format 1 에서 한 채널을 여러 트랙이
공유하면 규격과 다른 음색이 잡힌다. `mido.merge_tracks` 로 파일 전체를 시간
순으로 훑어 채널별 음색 이력을 만들고(`build_program_timeline`), 음표마다
그 타격 시점에 걸려 있던 값을 이분 탐색으로 찾는다(`program_at`).

`program_change` 가 앞서 없는 채널은 GM 기본값 0(Acoustic Grand Piano)으로 본다.
이 기본값 덕분에 **program_change 가 전혀 없는 단순 MIDI 는 전부 피아노로
판정되어 기존 동작이 그대로 유지된다.** 기준 코퍼스(ref_01~12)가 이 경우다.

## 2. 2단계 — 피아노 편곡 판정 (조건부)

1단계를 통과한 음표 중 피아노 음색의 점유율을 구하고,
`PIANO_ARRANGEMENT_SHARE` 이상이면 **피아노 음색 트랙만** 쓴다.
미달이면 이미 피아노 독주 편곡이 아니므로 1단계 결과를 그대로 쓴다.

피아노 음색 음표가 하나도 없으면 판정 자체를 하지 않는다(0% 로 미달 처리).

### 2.1 임계값 근거

§0.2 의 점유율 분포에는 뚜렷한 빈 구간이 있다.

```
0.0  4.6  6.7  12.5  26.3  39.9  56.7  66.0 |---- 빈 구간 ----| 100.0  100.0
                                                  (34 포인트)
```

66.0% 와 100.0% 사이에 곡이 하나도 없다. 피아노 독주 편곡(deb_clai,
Super Mario 64)은 100%이고, 혼합 편곡은 아무리 피아노 비중이 높아도 66% 를
넘지 않는다. **임계값은 이 빈 구간의 중간값으로 두었다.**

```
PIANO_ARRANGEMENT_SHARE = 0.80
```

0.70 ~ 0.95 구간에서 판정 결과가 모두 같으므로, 이 값은 소수점 자리에
민감하지 않다.

### 2.2 현재 코퍼스에서 2단계는 아무 일도 하지 않는다

θ = 0.80 에서 「피아노 트랙만」 판정을 받는 곡은 deb_clai 와
Super Mario 64 뿐이고, **두 곡은 이미 피아노 음색이 100%**다.
즉 **이번 측정에서 확인된 개선은 전부 1단계에서 나온 것이고, 2단계는
구현·검증만 되어 있으며 효과는 0이다.**

이것을 효과가 있는 것처럼 적지 않기 위해 따로 명시한다. 2단계가 실제로
작동하려면 "피아노 음색이 지배적이지만 100% 는 아닌" 입력, 예컨대 피아노
독주 악보에 메트로놈 트랙이나 코드 가이드 트랙이 붙은 MIDI 가 필요하다.
그런 입력은 코퍼스에 아직 없다.

## 3. 적용 결과

전 25곡(실곡 10 + 기준 코퍼스 12 + 합성 소품 3)에 대해 선별 기능만 켜고/끄고
같은 엔진으로 돌려 비교했다.

### 3.1 실곡 — 음표 손실

"운지 대상"은 선별·음역 필터를 통과해 DP 에 들어간 음표 수,
"제외"는 그 뒤 손 배정·화음 축소·순간 충돌 해소에서 빠진 음표 수다.

| 곡 | 운지 대상 (전→후) | 제외 (전→후) | 손실률 (전→후) |
|---|---|---|---|
| cac_kbo_bar | 1,572 → 1,109 | 276 → **0** | 17.6% → **0%** |
| nds-acww-0600 | 592 → 410 | 106 → **0** | 17.9% → **0%** |
| anicro_am1 | 500 → 154 | 5 → **0** | 1.0% → **0%** |
| cac_am3_gm | 444 → 315 | 31 → 5 | 7.0% → 1.6% |
| Queen - Bohemian Rhapsody | 4,506 → 3,615 | 533 → 335 | 11.8% → 9.3% |
| Driftveil_City_BW | 1,156 → 995 | 128 → 91 | 11.1% → 9.1% |
| wii-wiisports-titlescreen | 2,754 → 2,035 | 183 → 129 | 6.6% → 6.3% |
| nds-mkds-titlescreen | 3,059 → 1,673 | 189 → 174 | 6.2% → **10.4%** |
| Super Mario 64 - Medley | 5,406 → 5,406 | 0 → 0 | 0% → 0% |
| deb_clai | 1,491 → 1,491 | 0 → 0 | 0% → 0% |
| **실곡 합계** | 21,480 → 17,203 | **1,451 → 734** | **6.8% → 4.3%** |

**제외된 음표의 절대 수는 10곡 전부에서 줄거나 같다.** 세 곡은 0이 되었다.

`nds-mkds-titlescreen` 만 손실률이 6.2% → 10.4% 로 올랐는데, 이는 악화가
아니다. 제외 수는 189 → 174 로 줄었고 분모(운지 대상)가 3,059 → 1,673 으로
더 크게 줄어 비율만 오른 것이다. 드럼을 걷어내고 남은 손실은 실제 음정
자료에 집중되어 있다는 뜻이고, **남은 손실의 성격을 보려면 비율보다 절대
수를 봐야 한다**는 것을 보여 준다.

### 3.2 회귀 — 기준 코퍼스 12곡 결과 완전 동일

| 구분 | 곡 수 | 선별 ON/OFF 결과 |
|---|---:|---|
| 기준 코퍼스 ref_01~12 | 12 | **전곡 완전 동일** |
| 피아노 독주 실곡 (deb_clai, Super Mario 64) | 2 | **완전 동일** |
| 타악 포함 실곡 | 8 | 변화 (의도된 변화) |

기준 코퍼스는 연주 가능함이 보장된 합성 입력이고 전부 피아노 음색 단일
트랙이므로, 선별이 무엇을 해도 결과가 달라져서는 안 된다. 출력 JSON 을
음표 단위로 비교해 **완전 일치**를 확인했다. 이 비교는
`tests/test_track_selection.py` §3 에 회귀 테스트로 고정했다.

### 3.3 부수 효과

- 하드 제약 위반: 전후 모두 **0건** (25곡 전수)
- 미해결 시점: 전후 모두 **0건**
- 전체 처리 시간: 17.9s → 14.3s (DP 입력이 줄어든 만큼)

## 4. 남은 것

### 4.1 요구사항 3번 기준(노트 수가 가장 많은 트랙)은 채택하지 않았다

이 기준을 문자 그대로 적용하면 단일 트랙만 남는다. `deb_clai` 는
`Piano right`(712) 와 `Piano left`(779)가 별도 트랙이므로 **한 손이 사라진다.**
`Super Mario 64` 도 같다(2,708 / 2,727).

"가장 많은 트랙 하나"가 아니라 "양손을 덮는 트랙 집합"이어야 하므로,
요구사항의 표현 자체를 고치는 것이 맞다고 본다. 요구사항 분석서 수정이
필요한 항목으로 남긴다.

### 4.2 혼합 편곡의 남은 손실

1단계만으로 손실률이 6.8% → 4.3% 가 되었으나 0 은 아니다. 남은 손실은
`Bohemian Rhapsody`(335) · `nds-mkds`(174) · `wii-wiisports`(129) ·
`Driftveil`(91) 네 곡에 몰려 있고, 네 곡 모두 **두 손으로 동시에 연주할 수
없는 밴드 편곡**이다. 성부가 5개 이상 동시에 울리는 구간이 있다.

이것은 선별로 더 줄일 수 있는 양이 아니라 **편곡 자체의 연주 불가능성**이다.
3차 중간보고서 5.1.7 에서 정리한 구분(엔진 정확도 vs 입력 연주 가능성)에
따르면 후자에 해당하고, 엔진 정확도 검증은 기준 코퍼스로 한다.

다만 "성부 중요도 순 배정" 이 이 구간에서 어떤 성부를 버리는지는 아직
측정하지 않았다. 멜로디가 남는지 반주가 남는지는 확인이 필요하다.

### 4.3 2단계 검증용 입력 부재

§2.2 에 적은 대로, 2단계가 실제로 트랙을 걸러내는 입력이 코퍼스에 없다.
기준 코퍼스 생성기(`tools/make_reference_corpus.py`)에 "피아노 독주 + 비피아노
보조 트랙" 케이스를 추가하면 합성으로 만들 수 있다.
