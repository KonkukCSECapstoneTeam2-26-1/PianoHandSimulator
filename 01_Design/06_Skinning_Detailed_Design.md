# 고품질 디테일 스키닝 모듈 — 요구사항 및 설계

> 본 문서는 전체 "MIDI 기반 피아노 연주 시뮬레이션" 파이프라인 중 **마지막 단계인 메쉬 디테일 적용(고품질 디테일 스키닝)** 모듈을 다룬다.
> 디테일은 **텐션맵 · 핏줄맵 · 노멀맵** 을 활용해 주름·핏줄·미세 표면을 표현한다.
> 관련: `설계_다이어그램.md`, 결과 이미지 `images/wrinkle/`, 다이어그램 `images/diagrams/`

## 0. 프로젝트 범위 (Scope)

전체 시스템 단계:

`① MIDI→운지법 → ② IK(손가락 포즈·관절) → ③ Chaos Flesh(변형 표면·스트레인) → ④ 디테일 리소스(텐션맵·핏줄맵·노멀맵) → ⑤ [본 모듈] 고품질 디테일 스키닝 → ⑥ 최종 렌더 메쉬`

![전체 시스템 컨텍스트](images/diagrams/diagram-1.png)

- **상위 ①~④ (범위 밖)**: 본 모듈은 이들의 출력을 **입력으로 받아온다**고만 가정한다.
- **본 모듈 ⑤ (본 문서 범위)**: Chaos Flesh가 변형한 **표면 위에**, **텐션맵·핏줄맵·노멀맵**과 관절 정보를 받아 **주름·핏줄·미세(노멀) 디테일**을 얹어 고품질 표면을 출력한다.

> 핵심: **"거시 변형(물리) + 미시 디테일(셰이딩) 분리"**. 본 모듈은 *미시 디테일* 을 담당하며, **텐션맵(부위별 장력 필드)** 이 세 디테일 항을 공통 구동한다.

## 5-1. 기능요구사항 (Functional Requirements)

| ID | 요구사항 |
|---|---|
| FR1 | 상위 모듈/리소스로부터 **변형 표면, 관절 위치, 스트레인, 텐션맵, 핏줄맵, 노멀맵**을 입력받는다. |
| FR2 | Chaos Flesh가 변형한 **표면을 입력 메쉬로 사용**한다. (별도 메쉬 변환 없음) |
| FR3 | **텐션맵(부위별 장력)에 따라 주름 변위**를 생성한다(장력↑ → 주름↑). |
| FR4 | **핏줄맵과 텐션에 따라 핏줄 융기 변위**를 생성한다(장력↑ → 핏줄 도드라짐). |
| FR5 | **노멀맵을 텐션으로 블렌드**하여 미세 표면 디테일(모공·잔주름)을 셰이딩에 반영한다. |
| FR6 | 저밀도 표면에서도 **Nanite 테셀레이션(엔진 기능)을 활성**하여 기하 디테일을 표현한다. |
| FR7 | **관절/본 기반 마스크**로 디테일 적용 부위를 한정한다. |
| FR8 | 아티스트가 **디테일 맵(텐션·핏줄·노멀)과 파라미터**(주름 깊이/밀도, 핏줄 강도, 노멀 강도, 마스크 범위)를 저작·조정한다. |
| FR9 | 파라미터별 결과를 **시각적으로 검증·캡처**한다. |

## 5-2. 비기능요구사항 (Non-Functional Requirements / Qualities)

| 항목 | 요구사항 |
|---|---|
| 성능 (Performance) | 미시 디테일을 GPU(WPO/테셀/노멀)에서 처리하여 **실시간(≥30fps)** 유지 |
| 사용편리성 (Usability) | 맵/파라미터 변경이 **재컴파일 없이 즉시** 반영 |
| 이식성 (Portability) | 메쉬 종류 무관(Pre-Skinned 로컬 좌표 + UV 기반 맵) |
| 유지보수성 (Maintainability) | **표준 입력 인터페이스(맵 + 마스크 + 변형 표면)** 로 상위 모듈과 결합도 최소화 |
| 확장성 (Extensibility) | 디테일 항(주름/핏줄/노멀/…)을 **머티리얼 함수로 추가** 용이 |
| 제약 (Constraints) | Nanite 테셀+스켈레탈/Flesh는 UE5.6 실험적 → 미지원 시 고밀도 정적 메쉬로 폴백 |

## 5-3. 사용사례 (Use Cases — 기술서)

### UC1. 상위 입력·맵 수신
- **Actors**: IK/본, Chaos Flesh (외부 시스템)
- **Flow of Events**
  1. IK/본이 관절 위치를, Chaos Flesh가 변형 표면·스트레인을 전달한다.
  2. 구동 어댑터가 관절→마스크, 스트레인→**텐션맵**으로 변환하고 핏줄맵·노멀맵을 바인딩한다.
- **Exit condition**: 디테일 단계가 사용할 맵·마스크·구동 신호 준비
- **Exceptions**: 입력/맵 누락 시 직전 값 유지 또는 해당 항 생략
- **Special Requirements**: 프레임 지연 1 이내

### UC2. 주름 변위 생성
- **Actors**: (런타임 자동), 개발자/TA
- **Entry condition**: 변형 표면 + 텐션맵 + 관절 마스크
- **Flow of Events**
  1. Pre-Skinned 좌표로 마스크(smoothstep)를 만든다.
  2. 다중 사인 파형 × **텐션맵 샘플** × 마스크 × Amp 로 `disp_w` 를 계산한다.
  3. WPO에 적용한다.
- **Exit condition**: 압축 부위에 주름 생성
- **Exceptions**: 정점 밀도 부족 → UC5(테셀)로 보완

### UC3. 핏줄 변위 생성
- **Actors**: 아티스트(핏줄맵 저작), (런타임 자동)
- **Entry condition**: 핏줄맵 + 텐션맵
- **Flow of Events**
  1. 핏줄맵/SDF로 혈관까지 거리를 구하고 cos falloff로 융기를 만든다.
  2. `disp_v = ridge · (1 + 텐션·k) · VeinStrength` 로 장력 시 도드라지게 한다.
- **Exit condition**: 핏줄 융기 생성
- **Exceptions**: 핏줄맵 미제공 시 생략
- **Special Requirements**: 가시 부위(손등/전완 등)에서 효과 큼

### UC4. 노멀맵 미세 디테일
- **Actors**: 아티스트(노멀맵 저작)
- **Entry condition**: 디테일 노멀맵 + 텐션맵
- **Flow of Events**
  1. 디테일 노멀맵을 샘플링한다.
  2. **텐션맵으로 블렌드 강도를 조절**하여(압축 시 미세주름↑) 베이스 노멀에 섭동을 합성한다.
- **Exit condition**: 모공·잔주름 등 기하 변위 없는 미세 디테일이 셰이딩에 반영
- **Exceptions**: 노멀맵 미제공 시 베이스 노멀 사용
- **Special Requirements(성능)**: 기하 추가 없이 셰이딩만 → 저비용

### UC5. 테셀로 디테일 표현
- **Actors**: 개발자/TA
- **Flow of Events**
  1. 머티리얼·메쉬에 Nanite 테셀레이션(+디스플레이스먼트)을 활성/구성한다.
  2. 엔진이 정점을 적응적으로 생성·세분하여 기하 변위(주름·핏줄)를 표현한다.
- **Exceptions**: 스켈레탈+Nanite 테셀 미지원 → 정적 메쉬 경로
- **Special Requirements(성능)**: 실시간 유지

### UC6. 디테일 맵·파라미터 저작·튜닝
- **Actors**: 아티스트, 개발자/TA
- **Flow of Events**
  1. **텐션맵·핏줄맵·노멀맵**을 저작/지정한다.
  2. `Amp/Freq`(주름), `VeinStrength`(핏줄), `NormalStrength`(노멀), `JointC/R`(마스크)를 조정한다.
  3. 시스템이 뷰포트에 즉시 반영한다.
- **Special Requirements(사용편리성)**: 재컴파일 없이 1프레임 내 반영

### UC7. 결과 검증·캡처
- **Actors**: 개발자/TA
- **Flow of Events**: 파라미터 조합 지정 → 라이브로 값/카메라 설정 → 뷰포트 캡처
- **Exceptions**: 백그라운드 throttle → 창 직접 캡처로 우회

## 5-5. SW Architecture

### 5-5-1. Top-Level 구조
![SW Architecture](images/diagrams/diagram-2.png)

Chaos Flesh 변형 **표면을 입력 메쉬로 그대로 사용**하며, **2개 핵심 컴포넌트**로 구성된다.

### 5-5-2. 컴포넌트별 기능정의
| 컴포넌트 | 기능 정의 |
|---|---|
| **A. 구동 신호 어댑터** | 본/관절 → 부위 마스크, 스트레인 → **텐션맵**, 핏줄맵·노멀맵 바인딩. (상위 입력을 셰이더 신호·리소스로 표준화) |
| **B. 디테일 디스플레이스먼트 머티리얼** | 핵심. **① 주름 변위**(텐션맵·마스크·다중사인) + **② 핏줄 변위**(핏줄맵·텐션) 를 합성해 `WPO` 로 기하 변위, **③ 노멀 미세 디테일**(노멀맵 ⊗ 텐션)로 셰이딩 노멀 섭동. 저밀도면 **Nanite 테셀(엔진)** 활성. (내부도: `diagram-3`) |

### 5-5-4. 설계 가정 및 한계 (Assumptions & Limitations)
| ID | 가정/한계 | 근거 · 향후 |
|---|---|---|
| L1 | 주름은 물리 직접 유도가 아닌 **절차적(다중사인) 근사**이되 **텐션맵으로 부위별 변조**된다. | coarse 시뮬의 디테일 부재를 보완. 텐션맵으로 사실성 확보. |
| L2 | 구동은 **텐션맵(부위별 필드)** 으로 설계. (앞선 전역 스칼라 한계 해소) **단, 1단계 프로토타입 검증은 전역 스칼라로 수행**했고 맵 구동은 2단계에서 적용. | 상태도 1→2단계. |
| L3 | 디테일은 Chaos Flesh **렌더 표면 위에** 얹으며, 메쉬 간 변형 전이는 하지 않는다. | 별도 난제, 본 범위 불필요. |
| L4 | 테셀레이션은 **Nanite 엔진 기능 활성·구성**(자체 적응분할 미구현). | 엔진 제공 기능 활용. |
| L5 | 노멀맵 디테일은 **기하 변위 없는 셰이딩 디테일**(모공·잔주름). 텐션으로 강도 변조. | 저비용 고효율. |
| L6 | 핏줄 가시 효과는 **부위 의존**(손등/전완 큼, 손가락 작음). | 타깃 부위에 따라 강도 조절. |
