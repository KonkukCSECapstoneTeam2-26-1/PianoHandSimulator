## 4. 세부 내용

### 4.1 버그 수정

#### (1) Melody Continuity 비용 함수 부호 오류 수정
- **문제**: 멜로디 성부에서 인접 음이 순차 진행(Step Motion, 반음~온음 이동)할 때 같은 손가락을 유지하면 패널티를 부여하는 로직이 적용되어 있었음. 이는 레가토(Legato) 연주에 불리한 방향으로 작동하는 설계 오류였음.
- **수정**: 순차 진행 시 같은 손가락 유지 → **보상(-20)** 으로 전환. 반대로 도약(3반음 이상) 시 같은 손가락 고집 → **패널티(+30)** 추가.

#### (2) 넓은 화음 분리 함수의 루프 구조 버그 수정
- **문제**: `split_wide_chords_between_hands()` 함수에서 화음을 반대 손으로 분리한 뒤 수행되는 화음 병합(Merge) 단계가 `while` 루프 **바깥**에 위치하여, 병합 결과로 생성된 스팬 초과 화음이 재검사되지 않는 문제가 있었음. 이로 인해 단일 손에 32반음짜리 화음이 그대로 유지되는 현상이 발생.
- **수정**: 병합 단계를 `while` 루프 내부로 이동하여 split → merge → split 순서로 수렴할 때까지 반복 실행. 반대 손으로 분리 시 합산 스팬이 초과되는 경우 해당 음표를 drop하여 물리 불가 화음 완전 차단.
- **결과**: span 최대 32반음 → 14반음으로 감소.

#### (3) 5음 초과 화음 미처리 오류 수정
- **문제**: 화음 내 음표 수가 5개를 초과하면 `combinations(range(1,6), k>5)`가 빈 리스트를 반환하여 해당 화음의 운지법이 전혀 배정되지 않는 문제가 있었음.
- **수정**: `_trim_chord()` 함수를 추가하여 5음 초과 시 MELODY → BASS → INNER 우선순위로 중요 성부 음표 5개만 남기고 처리.

### 4.2 기능 개선

#### (4) MIDI 트랙 이름 기반 손 분리 도입
- **문제**: 기존 손 분리 로직이 피치 55를 고정 기준으로 사용하여, 멀티 트랙 MIDI 파일에서 Left/Right 트랙 정보를 전혀 활용하지 못하고 있었음.
- **수정**: `_detect_hand_from_track_name()` 함수를 추가하여 트랙 이름의 단어를 분리(`_`, 공백, `-` 구분자)한 뒤 Left/Right/Bass/Lead 등 키워드로 손을 결정. 키워드 미탐지 시 `_find_split_pitch()`로 전체 피치 분포의 밀도 최저점을 동적으로 탐색하여 분리 기준으로 사용.
- **효과**: `Piano right` / `Piano left` 트랙 정보를 가진 `deb_clai.mid`(드뷔시 Clair de Lune)에서 완벽한 손 분리 확인.

#### (5) Role Affinity 비용 함수 손별 분리 적용
- **문제**: 멜로디·베이스 성부의 손가락 선호도(Role Affinity)가 왼손·오른손 구분 없이 동일하게 적용되어 5번(새끼) 손가락이 전체 음표의 53%를 차지하는 과도 편중 현상 발생.
- **수정**: 해부학적 구조를 반영하여 손별로 다른 선호도 적용.
  - 오른손 MELODY: **4번(약지) 최선호** → 멜로디를 약지로 표현하는 피아노 표준 주법 반영
  - 왼손 BASS: **5번(새끼) 최선호** → 왼손에서 가장 낮은 음을 새끼로 담당하는 구조 반영
  - 오른손 BASS: **1번(엄지) 선호** → 오른손 내성부 베이스음 처리
- **결과**: 5번 사용 비율 53% → 33%로 감소. 전체 손가락 분포 균형화.

#### (6) 아르페지오 롤링 방향성 제약 추가
- **문제**: 연속 단음(아르페지오) 구간에서 DP가 동일 손가락을 반복 배정하거나, 피치가 상행하는데 손가락 번호가 역방향으로 배정되는 비자연스러운 운지법이 생성되었음.
- **수정**: 연속 단음 전환 시 피치 방향과 손가락 방향의 불일치에 +35 패널티, 동일 손가락 반복에 +60 패널티 추가. 왼손의 경우 손가락 방향이 오른손과 반대임을 반영(상행 = 5→1 방향 감소).
- **결과**: `anicro_am1.mid`에서 동음이 아닌 같은 손가락 연속 배정 **0회** 달성.

#### (7) 동시 누름 충돌 방지 로직 추가
- **문제**: 이전 음표의 지속시간(duration) 내에 같은 손가락에 다음 음표가 배정되면 물리적으로 두 건반을 동시에 누르는 불가능한 동작이 요구됨.
- **수정**: `calc_transition_cost()` 내에서 이전 화음 음표들의 `start_ms + duration_ms > 현재 시작 시간` 조건으로 아직 눌린 손가락 집합(`busy_fingers`)을 계산. 현재 화음에서 해당 손가락 재사용 시 +2500 패널티 부여.
